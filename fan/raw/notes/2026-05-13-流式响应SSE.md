⏺ IsStreamingResponse 流式响应解释

  在 OpenAI 兼容 API 中，有两种响应模式：

  非流式（普通）响应

  客户端发送请求后，等待服务器生成完整回答，一次性返回：

  客户端 ──请求──> vLLM 服务器

           （等待 5 秒，服务器生成完整内容...）

  客户端 <──完整 JSON 响应──

  {
    "choices": [{
      "message": {
        "content": "特斯拉成立于2003年，总部位于美国加州。"
      }
    }]
  }

  用户体验：5 秒内看不到任何内容，然后突然出现全部文字。

  ---
  流式（Streaming）响应 — IsStreamingResponse = true

  客户端请求时设置 "stream": true，服务器逐 token 推送，使用 SSE（Server-Sent Events）协议：

  客户端 ──请求 {"stream": true}──> vLLM 服务器

  客户端 <── data: {"choices":[{"delta":{"content":"特"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"斯"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"拉"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"成"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"立"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"于"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"2003"}}]}
  客户端 <── data: {"choices":[{"delta":{"content":"年"}}]}
  ...
  客户端 <── data: [DONE]

  用户体验：几乎立刻开始看到文字，一个字一个字地"打"出来（类似 ChatGPT 的打字效果）。

  ---
  在 processor_core.go 中的作用

  // 第 30-33 行
  if ctx.IsStreamingResponse && !ctx.StreamingComplete {
      ctx.StreamingAborted = true
      logging.Infof("Streaming response aborted before completion, will not cache")
  }

  这段逻辑的场景：

  ┌────────────────────────────────────────────────┬─────────────────────┬───────────────────┬───────────────────────────────┐
  │                      情况                      │ IsStreamingResponse │ StreamingComplete │             结果              │
  ├────────────────────────────────────────────────┼─────────────────────┼───────────────────┼───────────────────────────────┤
  │ 普通响应正常返回                               │ false               │ -                 │ 正常处理                      │
  ├────────────────────────────────────────────────┼─────────────────────┼───────────────────┼───────────────────────────────┤
  │ 流式响应完整接收（收到 [DONE]）                │ true                │ true              │ 可以缓存                      │
  ├────────────────────────────────────────────────┼─────────────────────┼───────────────────┼───────────────────────────────┤
  │ 流式响应中途断开（用户关闭浏览器、网络超时等） │ true                │ false             │ 标记 StreamingAborted，不缓存 │
  └────────────────────────────────────────────────┴─────────────────────┴───────────────────┴───────────────────────────────┘

  关键问题是：如果流式传输只发了一半就断了（比如只传了"特斯拉成立于"），这个不完整的响应不能被缓存，否则下次从缓存命中会返回截断的内容。

  RequestContext 中流式相关字段的生命周期

  handleRequestHeaders:  检测 Accept: text/event-stream → 设置 ExpectStreamingResponse
  handleResponseHeaders: 检测 Content-Type: text/event-stream → 设置 IsStreamingResponse
  handleResponseBody:    累积 SSE chunks → StreamingChunks/StreamingContent
                         收到 [DONE] → StreamingComplete = true
  Process (stream.Recv 出错): 如果未完成 → StreamingAborted = true
