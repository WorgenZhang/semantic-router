## AutoMix 公式各值的来源

```
V(model) = Quality(model) - λ × Cost(model) + γ × (1 - P_verify) × E[V(larger_model)]
```

逐项解释每个值如何得到：

---

### `Quality(model)` — 模型质量分 (0~1)

**来源方式**：通过历史评估数据统计得到。

- 在一个benchmark数据集上（或历史请求中），让该模型回答一批问题
- 用评估指标（如ROUGE、GPT-Judge打分、人工标注）给每个回答打分
- 取平均值作为该模型的 Quality

**举例**：8B模型在1000条测试问题上，平均得分0.75 → `Quality(8b) = 0.75`

---

### `λ` — 成本权衡系数

**来源方式**：人工设定的超参数，表示"你有多在乎成本"。

- `λ=0` → 完全不考虑成本，只看质量
- `λ=0.5`（默认）→ 质量和成本各占一半权重
- `λ=1` → 极度省钱模式

**调优方式**：根据业务需求手动设定，或通过grid search在验证集上找最优值。

---

### `Cost(model)` — 模型成本

**来源方式**：归一化后的推理成本。

- 原始成本 = 每百万token的价格（如 $0.5, $3.0, $10.0）
- 归一化：`Cost(model) = raw_cost / max_cost`

**举例**：
```
Cost(8b)   = 0.5 / 10.0 = 0.05
Cost(70b)  = 3.0 / 10.0 = 0.30
Cost(405b) = 10.0 / 10.0 = 1.00
```

---

### `γ` — 折扣因子

**来源方式**：人工设定的超参数（默认0.95），表示"对升级到更大模型的期望价值打多少折"。

- 类似强化学习中的discount factor
- `γ=1` → 完全信任升级的价值
- `γ=0` → 完全不考虑升级（退化为贪心选择）

---

### `P_verify` — 自我验证通过概率

**来源方式**：这是AutoMix最关键的创新点，通过**让模型自己判断答案是否正确**来估计。

具体做法（论文中的 Few-shot Self-Verification）：

1. 模型生成回答 answer
2. 把 `(question, answer)` 再次输入同一个模型，加上few-shot prompt问："这个回答正确吗？请给出置信度 0~1"
3. 模型输出一个置信度分数，即为单次的 `confidence`
4. `P_verify` = 该模型在历史数据上的**平均验证通过率**

**举例**：
- 8B模型回答了100个问题，其中65次自我验证说"我确信答案正确" → `P_verify(8b) = 0.65`
- 70B模型同样100个问题，85次通过验证 → `P_verify(70b) = 0.85`

---

### `E[V(larger_model)]` — 升级到更大模型的期望价值

**来源方式**：递归计算。从最大模型开始反向推导。

```
V(405b) = Quality(405b) - λ × Cost(405b) + 0   // 最大模型没有更大的可升级
V(70b)  = Quality(70b) - λ × Cost(70b) + γ × (1 - P_verify_70b) × V(405b)
V(8b)   = Quality(8b) - λ × Cost(8b) + γ × (1 - P_verify_8b) × V(70b)
```

**直觉理解**：`(1 - P_verify)` 是"验证失败的概率"，也就是"需要升级的概率"。这一项的含义是：

> "如果当前模型有 35% 的概率搞不定（验证失败），那我还有机会升级到更大模型获得额外价值"

---

### 完整计算流程（用文档中的例子）

```
V(405b) = 0.97 - 0.5×(10/10) + 0 = 0.47

V(70b)  = 0.90 - 0.5×(3/10) + 0.95×(1-0.85)×0.47
        = 0.90 - 0.15 + 0.95×0.15×0.47
        = 0.90 - 0.15 + 0.067
        = 0.817

V(8b)   = 0.75 - 0.5×(0.5/10) + 0.95×(1-0.65)×0.817
        = 0.75 - 0.025 + 0.95×0.35×0.817
        = 0.75 - 0.025 + 0.272
        = 0.997
```

8B的期望价值最高（0.997），因为它**便宜 + 失败了还能升级**，所以系统会优先尝试8B。

---

### 一句话总结

| 值 | 含义 | 来源 |
|---|---|---|
| Quality | 模型平均答对率 | 历史评估/benchmark |
| λ | 你多在乎钱 | 手动设定 |
| Cost | 归一化推理价格 | API定价/硬件成本 |
| γ | 升级价值的折扣 | 手动设定（默认0.95） |
| P_verify | 模型自信能搞定的概率 | 模型自我验证统计 |
| E[V(larger)] | 升级后能获得的价值 | 从大到小递归计算 |
