# 模型选择算法

## 概述

[[ModelSelector-Registry]] 支持 9 种模型选择算法，根据不同场景需求（冷启动、有反馈、成本敏感、数据充足等）选择合适的策略。

## 算法分类

### 在线方法（可动态学习，Go 运行时执行）

| 算法 | 核心思路 | 关键特征 |
|------|----------|----------|
| [[Static选择算法]] | 固定分数选最高 | 零延迟，适合冷启动 |
| [[Elo评分系统]] | 用户 A/B 反馈动态调整 rating | 自适应，需成对比较 |
| [[RouterDC]] | query-model embedding 相似度 | 语义匹配，无需历史数据 |
| [[AutoMix]] | POMDP 级联，小模型优先 | 成本-质量最优权衡 |
| [[Hybrid混合加权]] | 融合 Elo+RouterDC+AutoMix | 最鲁棒，开销最大 |

### ML 方法（Python 训练 → Rust 推理）

| 算法 | 核心思路 | 推理框架 |
|------|----------|----------|
| [[KNN选择算法]] | K 近邻质量加权投票 | [[Linfa]] |
| [[KMeans选择算法]] | 聚类+簇绑定模型 | [[Linfa]] |
| [[SVM选择算法]] | RBF 核决策边界 | [[Linfa]] |
| [[MLP选择算法]] | 神经网络 Softmax | [[Candle]] (GPU) |

## 选型指南

| 场景 | 推荐算法 | 原因 |
|------|----------|------|
| 刚上线，无数据 | Static | 零依赖 |
| 有用户反馈通道 | Elo | 自适应 |
| 模型能力描述清晰 | RouterDC | 语义匹配 |
| 控制成本为首要目标 | AutoMix | 级联省钱 |
| 追求最高准确率 | Hybrid / MLP | 综合/深度学习 |
| 历史路由数据丰富 | KNN / KMeans / SVM | 数据驱动 |
