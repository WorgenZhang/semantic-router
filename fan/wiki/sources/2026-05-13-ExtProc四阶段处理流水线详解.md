# ExtProc 四阶段处理流水线详解

## 核心观点

- 四阶段按顺序执行：请求头(SEND) → 请求体(BUFFERED) → 响应头(SEND) → 响应体(BUFFERED)
- **请求头阶段**只做"观察和记录"，不修改任何东西；真正的路由决策在 body 阶段
- **请求体阶段**是核心：Decision 评估 → 安全检查 → 缓存 → RAG → Memory → 模型路由
- **响应头阶段**注入 20+ 个 VSR 追踪 headers，提供完整可观测性
- **响应体阶段**处理 token 统计、缓存更新、幻觉检测

## 关键概念

- [[ExtProc]]：整体架构入口
- [[handleRequestHeaders]]：第一阶段，提取 headers、trace context、短路检查
- [[handleRequestBody]]：第二阶段，核心路由逻辑
- [[handleResponseHeaders]]：第三阶段，VSR headers 注入
- [[handleResponseBody]]：第四阶段，指标记录与后处理
- [[Decision Engine]]：信号评估 → Decision 匹配 → 模型选择
- [[Signal Evaluation]]：11 种信号类型评估
- [[RequestContext]]：贯穿请求生命周期的上下文结构体

## 请求体阶段的处理顺序（18 步）

1. 保存原始请求体
2. Response API 翻译
3. 流式参数提取
4. 解析 OpenAI 请求
5. 提取模型名
6. Looper 检测
7. 提取用户内容
8. **Decision 评估 & 模型选择**（核心）
9. Jailbreak 检测
10. PII 检测
11. 速率限制
12. 缓存查找
13. RAG 检索
14. Modality 路由
15. Memory 检索
16. **模型路由**（最终构建 HeaderMutation + BodyMutation）

## 短路点总结

| 短路条件 | HTTP 状态码 | 阶段 |
|---------|------------|------|
| Router Replay API | 200 | 请求头 |
| GET /v1/models | 200 | 请求头 |
| Response API GET/DELETE | 200 | 请求头 |
| Authz 失败 | 403 | 请求体 |
| Jailbreak 检测 | 403 | 请求体 |
| PII 策略违规 | 403 | 请求体 |
| 速率限制 | 429 | 请求体 |
| 缓存命中 | 200 | 请求体 |
| RAG 失败 + block 策略 | 503 | 请求体 |
| 幻觉检测 + block 策略 | 错误响应 | 响应体 |
