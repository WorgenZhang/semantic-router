# Signal 评估"宽进窄出"设计

## 核心观点

- 11 种信号分为两类：**驱动决策**的（7 种）和**服务于后处理**的（4 种）
- 当前实现选择一次性全部评估（`EvaluateAllSignalsWithHeaders()`），而非按需分两步
- 原因：共享 Embedding 计算、架构简洁、未来灵活性

## 必须在 Decision 前获取的信号（7 种）

Keyword、Embedding、Domain、Complexity、Language、Context、Authz — 构成 Decision 的 IF 条件

## 理论上可延后的信号（4 种）

Fact-check（→ 幻觉检测）、Modality（→ 路由执行）、User Feedback（辅助信号）、Preference（请求改写）

## 核心洞察

```
宽进：一次性算出所有 11 种信号（共享 embedding 计算）
窄出：Decision Engine 只消费 5-7 种作为规则条件
      剩余信号在后续步骤按需消费
```

## 关键概念

- [[Signal Evaluation]]：一次性评估所有信号
- [[Decision Engine]]：只消费部分信号作为规则条件
- [[幻觉检测]]：Fact-check 信号的真正消费者
