# 语义缓存（Semantic Cache）整体流程详解

## 一、核心结论：不涉及 KV Cache，纯粹基于 Embedding 相似度

这个项目中的"语义缓存"**与 LLM 推理层的 KV Cache 完全无关**。它是一个**应用层的请求-响应缓存**，核心思路是：

> 如果新请求和之前某个已缓存请求在**语义上足够相似**（embedding 余弦相似度 >= 阈值），就直接返回之前的响应，**跳过 LLM 推理**。

KV Cache 出现在代码库中仅限于 `candle-binding` 中的推理引擎（如 `prefix_cache.rs`），和语义缓存是完全独立的两个系统。

---

## 二、整体流程（请求的完整生命周期）

```
用户请求 → Envoy ExtProc → 请求分类 → 语义缓存查找 → [命中] → 直接返回缓存响应
                                           ↓ [未命中]
                                    RAG/路由/转发到 LLM
                                           ↓
                                    LLM 返回响应
                                           ↓
                                    写入语义缓存（UpdateWithResponse）
                                           ↓
                                    返回响应给用户
```

### 阶段 1：请求进入 — 提取查询文本

代码位置：`src/semantic-router/pkg/extproc/req_filter_cache.go:47`

```go
requestModel, requestQuery, err := cache.ExtractQueryFromOpenAIRequest(ctx.OriginalRequestBody)
```

从 OpenAI 格式的请求体中提取 `model` 和最后一条 `user` 消息作为查询文本。

### 阶段 2：缓存查找 — 生成 Embedding + 相似度比较

代码位置：`src/semantic-router/pkg/cache/inmemory_cache.go:460` (`FindSimilarWithThreshold`)

1. **生成查询 Embedding**：调用 `generateEmbedding(query)`，通过 candle-binding 调用 BERT/Qwen3/Gemma/mmBERT 模型生成向量（`inmemory_cache.go:177-211`）
2. **搜索最相似条目**：
   - **HNSW 模式**（启用时）：使用 HNSW 图索引做近似最近邻搜索，取 Top-10 候选（`inmemory_cache.go:508`）
   - **线性搜索模式**（默认）：遍历所有 entries，计算 dot product
3. **相似度判断**：`bestSimilarity >= threshold` 即为缓存命中（`inmemory_cache.go:603`）

### 阶段 3a：缓存命中 — 立即返回

代码位置：`src/semantic-router/pkg/extproc/req_filter_cache.go:98-129`

命中后直接构造 `ProcessingResponse`，通过 Envoy 返回给客户端，**完全跳过后端 LLM**。

### 阶段 3b：缓存未命中 — 写入 Pending + 等待响应

代码位置：`req_filter_cache.go:140-141` 和 `processor_res_body.go:221`

1. `AddPendingRequest`：在缓存中创建一个**只有请求、没有响应**的条目（此时就已经生成了 Embedding）
2. 请求正常路由到 LLM
3. LLM 响应返回时调用 `UpdateWithResponse`，将响应体补充到 pending 条目中

## 三、支持的四种存储后端

| 后端类型 | 类型标识 | 搜索方式 | 适用场景 |
|---------|---------|---------|---------|
| **In-Memory** | `memory` | 线性扫描 / HNSW 图索引 | 单实例、低延迟 |
| **Redis** | `redis` | Redis Vector Search (HNSW/FLAT) | 分布式、持久化 |
| **Milvus** | `milvus` | Milvus 向量数据库 | 企业级、大规模 |
| **Hybrid** | `hybrid` | 内存 HNSW + Milvus 溢出 | 热数据快、冷数据不丢 |

---

## 四、淘汰与过期策略

- **TTL 过期**：支持全局 TTL 和 per-entry TTL，使用 `ExpirationHeap`（最小堆）实现 O(k) 清理
- **淘汰策略**：当条目数达到 `max_entries` 时触发，支持三种 O(1) 策略：
  - **FIFO**（默认）：先进先出
  - **LRU**：最近最少使用
  - **LFU**：最不经常使用
- **滑动窗口 TTL**：每次缓存命中会延长该条目的过期时间

## 五、具体案例说明

### 案例 1：完全相同的问题 — 缓存命中

```
请求 A: "什么是量子计算？"  →  生成 embedding_A  →  无缓存  →  LLM 返回响应  →  存入缓存
请求 B: "什么是量子计算？"  →  生成 embedding_B  →  dot_product(A, B) = 0.99 >= 0.85  →  缓存命中！直接返回 A 的响应
```

**效果**：请求 B 完全跳过 LLM 推理，延迟从数秒降到毫秒级。

### 案例 2：语义相似的改写 — 缓存命中

```
请求 A: "请解释一下什么是机器学习"    →  存入缓存
请求 B: "能给我介绍下机器学习的概念吗" →  生成 embedding  →  similarity = 0.91 >= 0.85  →  缓存命中！
```

**关键点**：两个请求的文字不同，但因为 BERT/Qwen3 embedding 捕获了语义相似性，dot product 超过了阈值 0.85，所以仍然命中。

### 案例 3：语义不同的问题 — 缓存未命中

```
请求 A: "什么是量子计算？"        →  存入缓存
请求 B: "今天北京天气怎么样？"     →  生成 embedding  →  similarity = 0.12 < 0.85  →  缓存未命中
```

**结果**：请求 B 正常路由到 LLM。B 的响应返回后也会被缓存，供后续类似请求使用。

### 案例 4：同一问题、不同 model — 后端行为差异

当前代码中 `FindSimilarWithThreshold` 接收 `model` 参数但 InMemory 实现实际上在线性搜索中**没有按 model 过滤**（只做了 embedding 相似度比较）。不过在 Milvus/Redis 后端中，model 字段会作为过滤条件。这意味着：

```
请求 A: model="gpt-4", query="什么是AI"  →  存入缓存
请求 B: model="gpt-3.5", query="什么是AI" →  在 Milvus 后端会未命中（model 不匹配），InMemory 后端会命中
```

### 案例 5：per-category 阈值 — 不同分类不同标准

```yaml
decisions:
  - name: "code_generation"
    cache:
      enabled: true
      similarity_threshold: 0.95  # 代码类问题要求更高相似度
  - name: "general_chat"
    cache:
      enabled: true
      similarity_threshold: 0.80  # 闲聊类问题可以更宽松
```

```
请求 A（分类=general_chat）: "推荐一部好看的电影"  →  存入缓存
请求 B（分类=general_chat）: "有什么好电影推荐？"   →  similarity=0.82 >= 0.80  →  命中

请求 C（分类=code_generation）: "写一个快排算法"    →  存入缓存
请求 D（分类=code_generation）: "帮我写个排序算法"   →  similarity=0.88 < 0.95   →  未命中（阈值更严格）
```

### 案例 6：TTL 过期 — 缓存条目超时

```
请求 A（t=0s）: "最新的AI新闻"  →  存入缓存，TTL=3600s
请求 B（t=3500s）: "最新的AI新闻" →  similarity=0.99, 且 3500 < 3600  →  命中！TTL 滑动窗口延长到 t+3600
请求 C（t=7500s）: "最新的AI新闻" →  该条目在 t=7100s（3500+3600）到期  →  已被后台清理  →  未命中
```

## 六、总结

| 维度 | 说明 |
|------|------|
| **缓存类型** | 应用层语义缓存，非推理层 KV Cache |
| **核心机制** | Embedding 余弦相似度（dot product on normalized vectors） |
| **Embedding 模型** | BERT（默认）/ Qwen3 / Gemma / mmBERT |
| **搜索算法** | 线性扫描 或 HNSW 近似最近邻 |
| **存储后端** | InMemory / Redis / Milvus / Hybrid |
| **淘汰策略** | FIFO / LRU / LFU + TTL 过期堆 |
| **缓存粒度** | 完整的请求-响应对（request body + response body） |
