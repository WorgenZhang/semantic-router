# NPU 周期内帧时间戳策略：同帧锁存 vs 最新帧

## 核心问题

在一个 100ms 时间窗口内，不同 Use Case 使用的 camera 流是同一时间戳的帧，还是每个 UC 执行时取最新的帧？

---

## 结论：同一周期内使用同一时间戳的帧（周期起始时锁存）

```
周期开始 t=0ms
  ↓
Frame Buffer 锁存：
  MPIC_frame[t=0]  ← 所有需要 MPIC 的 UC 共用这一帧
  FWC_frame[t=0]   ← 所有需要 FWC 的 UC 共用这一帧
  SCF_L_frame[t=0] ← 所有需要 SCF_L 的 UC 共用这一帧
  SCF_R_frame[t=0] ← 所有需要 SCF_R 的 UC 共用这一帧
  FTC_frame[t=0]   ← 所有需要 FTC 的 UC 共用这一帧
  ↓
整个 100ms 周期内，NPU 处理的都是 t=0 锁存的帧
```

---

## 为什么不能用"处理到谁就取最新帧"

### 1. 时间一致性要求（Safety 关键）

uc11 的 `sync_late_fusion` 需要将 FWC + SCF_L + SCF_R 三路结果融合。如果：
- FWC 用的是 t=0ms 的帧
- SCF_L 用的是 t=57ms 的帧

融合结果在物理上不对应同一场景瞬间，safety 判断会出错。

例如：行人在 t=0 时刚进入 FWC 画面边缘，在 t=57ms 时已经进入 SCF_L 画面中部——两帧融合可能误判为"两个行人"或计算出错误的位置。

### 2. Backbone 共享机制依赖同帧

`same_backbone_shared=true` 意味着同一次 Backbone 推理的输出被多个 UC 的 Head 复用：

```
Backbone_B(FWC_frame[t=0]) 的输出 →
  head_b3 → uc11 (特殊车辆检测)
  head_b4 → uc13 (场景分类)
  head_b1 → uc10 (天气识别)
  head_b2 → uc10 (光照识别)
```

如果每个 UC 取不同时间的帧，就无法共享 Backbone，每个 UC 都要独立跑一次推理，NPU 时间直接爆炸。

### 3. CV 和 ViT 并行 Merge 的前提

`cv_vit_parallel` 模式下：
```
NPU-CV: cv_child_det(MPIC_frame[t=0]) → 输出儿童检测结果
NPU-ViT: Backbone_A(MPIC_frame[t=0]) → head_a2 → 输出人群分类结果
                                         ↓
                             Parallel Merge: 两个结果对应同一帧
```

如果时间戳不同，Merge 在语义上就不成立。

## 帧时间戳策略全景

```
┌────────────────────────────────────────────────────────────────────────┐
│ 场景                    │ 帧时间戳策略                                  │
├────────────────────────────────────────────────────────────────────────┤
│ 同一 Backbone 输出      │ 必定同帧                                      │
│ 被多个 Head 复用        │ 一次推理只有一个输入帧                        │
├────────────────────────────────────────────────────────────────────────┤
│ 同一相机流              │ 同帧 — 周期起始时锁存，本周期内不更新          │
│ 被不同 UC 使用          │ 例: uc17 和 uc5 都用 MPIC_frame[t=0]          │
├────────────────────────────────────────────────────────────────────────┤
│ 不同相机流              │ 各流独立锁存于同一时刻（硬件同步触发）          │
│ 同一 UC 需要融合        │ 例: uc11 的 FWC/SCF_L/SCF_R 都是 t=0 采集     │
├────────────────────────────────────────────────────────────────────────┤
│ 跨周期（交错调度复用）   │ 不同帧！用上轮锁存帧                          │
│                         │ Late Fusion 通过 weights 补偿时间偏移          │
└────────────────────────────────────────────────────────────────────────┘
```

---

## 唯一例外：交错调度的跨周期复用

方案 B 中 SCF_L/SCF_R 交替调度，未被调度的那一路使用上一周期的结果：

```
周期 N (t=0ms):
  处理: FWC[t=0] + SCF_L[t=0]
  复用: SCF_R 使用周期 N-1 (t=-100ms) 的结果

周期 N+1 (t=100ms):
  处理: FWC[t=100] + SCF_R[t=100]
  复用: SCF_L 使用周期 N (t=0ms) 的结果
```

### 时间偏移补偿

通过加权融合解决 100ms 的时间差：

```
uc11 Late Fusion weights:
  FWC_current:          0.50  ← 当前帧，权重最高
  SCF_L_current_or_prev: 0.25  ← 可能是上轮帧，权重降低
  SCF_R_current_or_prev: 0.25  ← 可能是上轮帧，权重降低
```

设计理由：
- 当前帧权重高(0.5)：保证实时性
- 上轮帧权重低(0.25)：提供辅助信息但不主导判断
- 100ms 偏移在车辆 120km/h 时约 3.3m 位移，侧方辅助摄像头对这个级别的偏移容忍度较高

## 帧锁存的实现机制

```
┌─────────────────────────────────────────────────────────────┐
│                    主周期调度器                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  每 100ms 触发一次:                                         │
│                                                             │
│  1. 硬件同步信号 → 所有相机同时采集                          │
│     (或取各相机最近一帧，容差 < 5ms)                         │
│                                                             │
│  2. 锁存到 FrameBuffer:                                     │
│     frame_buffer = {                                        │
│       MPIC: cam_mpic.latest_frame,   // timestamp ≈ t      │
│       FWC:  cam_fwc.latest_frame,    // timestamp ≈ t      │
│       SCF_L: cam_scf_l.latest_frame, // timestamp ≈ t      │
│       SCF_R: cam_scf_r.latest_frame, // timestamp ≈ t      │
│       FTC:  cam_ftc.latest_frame,    // timestamp ≈ t      │
│     }                                                       │
│                                                             │
│  3. 将 frame_buffer 传入本周期的调度队列                     │
│     - NPU-ViT 队列中所有任务从 frame_buffer 取输入          │
│     - NPU-CV 队列中所有任务从 frame_buffer 取输入           │
│                                                             │
│  4. 本周期结束前，frame_buffer 不更新                        │
│     (即使相机已产出新帧，也要等下一周期才锁存)               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 总结

| 问题 | 答案 |
|------|------|
| 同一周期内不同 UC 用同一帧吗？ | **是**，周期起始锁存，整个周期内不变 |
| 同一周期内 CV 和 ViT 用同一帧吗？ | **是**，parallel merge 的前提 |
| 跨周期复用的帧时间戳一致吗？ | **否**，有 100ms 偏移，通过权重补偿 |
| 为什么不用最新帧？ | 破坏融合一致性、无法共享 Backbone、safety 判断错误 |
