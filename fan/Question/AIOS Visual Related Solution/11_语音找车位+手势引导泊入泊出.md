## ADAS 停车用户指示 & 舱外手势识别：摄像头 + 模型方案

---

### 功能拆解

```
三个子功能:

1. 语音引导找车位 (Voice-Guided Spot Search)
   → 用户说"找电梯旁的车位"/"去B2层"/"找充电桩"
   → 车辆自主巡航寻找符合条件的车位

2. 语音/手势引导泊入泊出 (Guided Park-in/out)
   → 车外的人用手势指挥车辆前进/停止/转向
   → 或车内语音指令 "再往前一点"/"停"

3. 舱外人员手势识别 (Exterior Gesture Recognition)
   → 识别车外人（车主/引导员）的手势指令
   → 控制车辆低速移动
```

---

### 功能 1：语音引导找车位

#### 需要识别什么

```
用户说"找电梯旁的"
  → 需要识别: 电梯间（门/标识牌/墙面指示）

用户说"去B2层"
  → 需要识别: 楼层标识（墙面"B2"字样/层号牌）

用户说"找充电桩"
  → 需要识别: 充电桩实体 + 绿色车位标识

用户说"找无障碍车位"
  → 需要识别: 轮椅图标 + 蓝色标线 + 宽车位

用户说"找宽敞的车位"
  → 需要识别: 车位宽度 + 两侧是否有车 + 柱子距离

用户说"找靠近出口的"
  → 需要识别: 出口指示牌/箭头/出口通道
```

#### 摄像头配置

```
┌──────────────────────────────────────────────────┐
│         语音找车位 - 摄像头需求                    │
│                                                  │
│  巡航阶段 (低速行驶寻找中):                       │
│                                                  │
│  FWC: 前方标识牌识别（电梯/楼层/出口指示）         │
│       前方空车位检测（5~20m）                      │
│       充电桩/无障碍标志识别                        │
│                                                  │
│  SC_FL + SC_FR: 两侧车位状态扫描                  │
│       车位是否有车/是否够宽/是否有柱子             │
│       侧方墙面楼层标识                            │
│                                                  │
│  SVC (四路): 近距离环境感知                        │
│       低速避障（行人/购物车/柱子）                 │
│       车位线精确定位                              │
│       两侧车辆边界精确感知                        │
│                                                  │
└──────────────────────────────────────────────────┘
```

#### 模型需求

```
CV 模型 (车端实时):
  → 车位检测: 空/占用/半占用 分类
  → 车位线分割: 精确定位可泊入区域
  → 目标检测: 充电桩/电梯门/指示牌/柱子/障碍物
  → 车位宽度估算: 结合两侧车辆或柱子的距离

OCR (车端):
  → 读取楼层号: "B1"/"B2"/"F3"
  → 读取指示牌: "电梯→"/"出口↑"/"充电区"
  → 读取车位编号

VLM (车端/云端 - 理解用户意图与环境匹配):
  → "靠近电梯" → VLM 理解电梯间的环境特征（不只是看牌子）
  → "宽敞的" → VLM 综合判断多个空位哪个最宽敞
  → 但大多数情况 CV + OCR + 规则 足够，VLM 作为兜底

算力: ~8-10 TOPS (CV + OCR)
```

### 功能 2：语音/手势引导泊入泊出

#### 场景描述

```
场景 A: 车内语音引导
  驾驶员坐在车内，APA 正在泊车
  "再前面一点" / "够了停" / "方向打多了"
  → 这个不需要额外摄像头，用麦克风 + NLP 即可

场景 B: 车外遥控泊车 (关键场景)
  车主站在车外（如车位太窄下不了车）
  通过手机 App 操控 + 车外手势辅助
  车需要"看到"车外的人在做什么手势

场景 C: 代客泊车/他人引导
  停车场引导员用手势指挥车辆
  "往前开" / "停" / "往左打"
```

#### 摄像头配置

```
┌──────────────────────────────────────────────────┐
│       手势引导泊入泊出 - 摄像头需求               │
│                                                  │
│  车外人员可能在任何位置:                           │
│                                                  │
│  车主在前方 → FWC + SVC_F                        │
│  车主在后方 → RVC + SVC_R                        │
│  车主在左侧 → SC_FL + SVC_SL                    │
│  车主在右侧 → SC_FR + SVC_SR                    │
│                                                  │
│  需要 360° 覆盖:                                 │
│  人可能从任何方向发出手势                         │
│                                                  │
│  同时需要:                                       │
│  → 看清人的手势（需要足够分辨率）                  │
│  → 看清周围障碍物（安全保障）                      │
│  → 两者必须同时满足                              │
└──────────────────────────────────────────────────┘
```

### 功能 3：舱外人员手势识别（核心）

#### 需要识别的手势

```
安全控制类 (最高优先级):
  🖐️ 举手掌/停止手势 → 紧急停车 (任何人都可触发)
  
方向控制类:
  👋 手臂向前挥 → 前进
  ✋ 手臂向后挥 → 后退
  👈 手臂向左指 → 左转
  👉 手臂向右指 → 右转
  
确认类:
  👍 竖大拇指 → 确认/到位了
  ✌️ OK 手势 → 继续当前操作

速度类:
  手掌下压 → 慢一点
  手掌快速挥动 → 快一点（在安全范围内）
```

#### 手势识别的技术挑战

```
难点 1: 距离变化大
  车主可能在 1m（车旁）到 10m（远处观察）
  → 人在 1m 时手势占画面极大
  → 人在 10m 时手势只占几十像素

难点 2: 方向不确定
  不知道人站在车的哪个方向
  → 需要先检测人在哪 → 再用对应摄像头识别手势

难点 3: 光照环境恶劣
  地下停车场: 光照弱、有阴影、荧光灯闪烁
  → 需要对低光环境鲁棒

难点 4: 安全性要求极高
  手势识别错误 → 车辆错误移动 → 可能撞人
  → 需要高置信度才执行
  → 需要多帧确认（不能单帧误触发）
```

#### 摄像头选择

```
┌──────────────────────────────────────────────────────────┐
│              舱外手势识别 - 摄像头方案                      │
│                                                          │
│  阶段 1: 人员检测 + 定位（"人在哪"）                       │
│                                                          │
│    摄像头: 4路 SVC 鱼眼                                    │
│    原因: 360° 覆盖，不管人在哪个方向都能找到               │
│    输出: 人的位置 + 在哪个方向                             │
│                                                          │
│  阶段 2: 手势识别（"人在做什么"）                          │
│                                                          │
│    摄像头: 对应方向的 SC（主）+ SVC（辅）                  │
│                                                          │
│    人在前方 → FWC (8MP，手势细节最清晰)                   │
│    人在左侧 → SC_FL (3MP，H120° 正好覆盖人体范围)        │
│    人在右侧 → SC_FR                                      │
│    人在后方 → RVC (3MP)                                  │
│                                                          │
│    为什么用 SC 而不只用 SVC:                               │
│    → SVC 鱼眼畸变导致手势形状变形                         │
│    → SVC 像素密度低，5m 外手掌只有十几像素                │
│    → SC 无畸变，像素密度高，手势形状保持正确               │
│                                                          │
│  阶段 3: 安全确认（"周围安全吗"）                          │
│                                                          │
│    摄像头: 4路 SVC + FWC/RVC                              │
│    原因: 手势说"往前开"，但前方有障碍物 → 不能执行         │
│    必须同时确认行进方向安全                                │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 手势识别在不同距离下的像素分析

```
假设目标: 识别"举手掌"手势，手掌宽度约 10cm

在 SC_FL (H120°, 1960px) 中:
  像素密度: 1960 ÷ 120° = 16.3 px/°

  3m 距离: 手掌占 arctan(0.1/3) ≈ 1.9° → 31px ← 可识别 ✅
  5m 距离: 手掌占 arctan(0.1/5) ≈ 1.1° → 18px ← 勉强 △
  8m 距离: 手掌占 arctan(0.1/8) ≈ 0.7° → 11px ← 困难 ❌

在 FWC (H120°, 3840px) 中:
  像素密度: 3840 ÷ 120° = 32 px/°

  3m 距离: 手掌占 1.9° → 61px ← 清晰 ✅✅
  5m 距离: 手掌占 1.1° → 35px ← 可识别 ✅
  8m 距离: 手掌占 0.7° → 22px ← 勉强可 △

结论:
  FWC 前方最远可识别到 ~8m
  SC 侧方最远可识别到 ~5m
  超过这个距离 → 需要识别整体手臂动作而非手掌细节
```

### 模型方案

```
┌──────────────────────────────────────────────────────────┐
│             舱外手势识别 - 模型架构                         │
│                                                          │
│  [Model 1: 人体检测 + 姿态估计] — CV                       │
│                                                          │
│   输入: SVC/SC/FWC 画面                                   │
│   输出: 人体关键点 (17~25 个骨骼点)                        │
│         特别关注: 肩/肘/腕/手指 关键点                     │
│   模型: 轻量姿态估计 (MoveNet / MediaPipe 级别)            │
│   算力: ~2 TOPS                                          │
│   延迟: <50ms                                            │
│                                                          │
│  [Model 2: 手势分类] — CV                                  │
│                                                          │
│   输入: 手部 ROI 区域 (从 Model 1 裁切)                   │
│   输出: 手势类别 (停止/前进/后退/左/右/确认/未知)          │
│   模型: 轻量分类网络                                      │
│   算力: ~1 TOPS                                          │
│   延迟: <30ms                                            │
│                                                          │
│  [Model 3: 动作序列识别] — CV (时序)                       │
│                                                          │
│   输入: 连续多帧骨骼点序列 (0.5~1 秒)                    │
│   输出: 动态手势 (挥手方向/速度指令)                       │
│   模型: 轻量时序网络 (TCN / LSTM)                         │
│   算力: ~1 TOPS                                          │
│   延迟: ~200ms (需要积累多帧)                             │
│                                                          │
│  [安全逻辑层] — 规则引擎                                   │
│                                                          │
│   多帧确认: 同一手势持续 >0.5s 才执行                     │
│   置信度门槛: >0.9 才响应（宁可不动也不误动）              │
│   安全否决: 行进方向有障碍物 → 忽略前进手势               │
│   紧急停止: "停止"手势优先级最高，单帧即停                │
│                                                          │
│   总算力: ~4-5 TOPS                                      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 是否需要 VLM？

```
手势识别本身: ❌ 不需要 VLM
  → 手势是预定义的有限类别（<10种）
  → 实时性要求高（<100ms 响应）
  → 安全关键场景需要确定性输出
  → CV 姿态估计 + 分类完全够用

语音找车位的意图理解: ✅ 需要 NLP/LLM
  → "找个电梯旁边宽敞的充电车位" 
  → 需要理解多条件组合
  → 但这是语言模型的活，不是视觉模型的活

整体流程:
  语音 → LLM 理解意图 → 拆解为搜索条件
  搜索条件 → CV 视觉识别 → 匹配目标车位
  泊车中 → CV 手势识别 → 控制车辆移动
  
  全程不需要 VLM（不需要"看图理解"）
```

### 手势识别安全设计原则

```
原则 1: 宁停勿动
  识别不确定时 → 停车等待
  不会因为"可能是前进手势"就前进

原则 2: 停止优先
  "停止"手势: 单帧 + 置信度 >0.7 即停
  "前进"手势: 连续 15 帧 (0.5s) + 置信度 >0.9 才动

原则 3: 安全否决权
  即使手势说"前进"，障碍物检测说"前方有人" → 不动

原则 4: 人员绑定
  只响应已授权人员的手势（通过身份识别绑定）
  路人的"停止"手势除外（任何人都可以停车）

原则 5: 速度限制
  手势控制下最高速度: 5km/h
  无论什么手势都不会超过这个速度
```

```
  人体检测: ~1 TOPS

  手势分类: ~1 TOPS
  动作序列: ~1 TOPS
  小计: ~5 TOPS

安全保障 (全程):
  障碍物检测: ~2 TOPS
  行人检测: ~2 TOPS
  小计: ~4 TOPS

总计峰值: ~12-15 TOPS (找车位 + 安全同时运行)
```

### 一句话总结

ADAS 停车用户指示需要 **全部摄像头协同工作**：FWC 负责前方标识和手势识别，SC 负责侧方车位扫描和侧向手势，SVC 负责 360° 近距离避障和人员检测，RVC 负责倒车和后方手势。模型全部用 **CV 小模型**（姿态估计 + 手势分类 + 目标检测 + OCR），不需要 VLM。语音意图理解由 LLM 处理，视觉部分只负责"看到什么"而非"理解什么意思"。
