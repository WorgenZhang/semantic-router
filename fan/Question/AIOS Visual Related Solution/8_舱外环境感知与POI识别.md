## 舱外环境感知 & POI 识别：摄像头 + 模型方案

---

### 功能分层

| 功能 | 核心需求 | 实时性要求 |
|------|---------|-----------|
| 盲区车辆/行人感知 | 安全相关，准确检测 | 高（毫秒级） |
| 天气/光照感知 | 环境大类判断 | 低（秒级） |
| 车外闲聊（"外面是什么"） | 理解场景语义 | 中（1~3秒可接受） |
| 景点/楼栋识别 | 认出具体地标 | 中 |
| POI 回答（"旁边的河叫什么"） | 识别 + 知识关联 | 中 |

### 各功能详细分析

#### 1. 盲区车辆/行人感知（安全提醒）

```
摄像头: SC_FL + SC_FR + SC_RL + SC_RR（侧向 4 路）
        SVC_SL + SVC_SR（近距离补充）

模型: CV 小模型（不需要 VLM）
  → 目标检测: YOLO 级别，检测车辆/行人/骑行者
  → 距离估算: 单目测距或多路融合
  → 运动预测: 轨迹预测判断碰撞风险

为什么不需要 VLM:
  → 安全场景要求延迟 <50ms
  → 只需要"有没有/在哪里/多远"，不需要"是什么牌子的车"
  → CV 小模型完全够用
```

#### 2. 天气/光照感知

```
摄像头: FWC 为主（看天空和前方能见度）

模型: CV 分类模型（轻量）
  → 天气分类: 晴/阴/雨/雪/雾
  → 光照判断: 白天/黄昏/夜间/隧道/逆光
  → 能见度估算: 远处目标清晰度分析

怎么判断:
  FWC 画面上半部分 = 天空区域
  → 灰暗 + 雨滴纹理 = 下雨
  → 白茫茫一片 = 大雾
  → 整体亮度低 + 车灯反射 = 夜间

输出给谁:
  → 氛围灯联动（雨天蓝色、晴天暖色）
  → 语音提醒（"前方能见度较低，建议减速"）
  → 自动开关大灯/雨刷的辅助判断
```

#### 3. 车外通用闲聊 & 景点识别

```
摄像头: FWC + SC_FL + SC_FR（前方 + 两侧）

模型: ✅ 需要 VLM

为什么需要 VLM:
  用户问题是开放式的:
    "外面是什么地方？"
    "右边那栋建筑是什么风格？"
    "前面那座山叫什么？"

  → CV 小模型只能输出"建筑物/山/水体"这种标签
  → VLM 能输出"这是一座哥特式教堂，尖塔和玫瑰窗是特征"
  → VLM 能结合知识回答"这条河可能是黄浦江"

摄像头选择逻辑:
  用户问"前面" → 取 FWC 画面送 VLM
  用户问"右边/旁边" → 取 SC_FR 画面送 VLM
  用户问"周围" → 取 FWC + SC_FL + SC_FR 多图送 VLM
```

#### 4. POI 识别（"车旁边的河是什么河"）

```
摄像头: 根据用户问的方向选择对应摄像头

模型: VLM + GPS + 地图 POI 数据库联合

识别流程:
  ┌──────────────────────────────────────────┐
  │ 用户: "车旁边的河是什么河？"              │
  │                                          │
  │ Step 1: 语义理解                          │
  │   "旁边" → 侧方 → 取 SC_FL 或 SC_FR     │
  │   "河" → 目标类型 = 水体                  │
  │                                          │
  │ Step 2: 视觉确认                          │
  │   SC_FR 画面送 VLM                        │
  │   VLM 确认: "画面右侧有一条宽阔河流"      │
  │                                          │
  │ Step 3: POI 关联                          │
  │   当前 GPS: (31.23°N, 121.47°E)          │
  │   查询地图 POI: 该坐标附近的水体          │
  │   匹配结果: 黄浦江                        │
  │                                          │
  │ Step 4: 回答生成                          │
  │   "您右侧的河是黄浦江，全长约 113 公里，  │
  │    是上海的母亲河。"                       │
  └──────────────────────────────────────────┘
```

### 模型方案总结

```
┌─────────────────────────────────────────────┐
│              模型分层架构                      │
│                                             │
│  [实时层 - CV 小模型] (车端运行)              │
│   • 目标检测（车辆/行人/骑行者）              │
│   • 天气/光照分类                            │
│   • 运动检测                                 │
│   延迟: <50ms | 算力: 2~5 TOPS              │
│                                             │
│  [理解层 - VLM] (车端或云端)                  │
│   • 场景语义理解（"这是什么地方"）             │
│   • 地标/建筑识别                            │
│   • 开放式问答                               │
│   延迟: 1~3s | 算力: 10~30 TOPS             │
│                                             │
│  [知识层 - LLM + 知识库] (云端)               │
│   • POI 名称关联                             │
│   • 景点介绍生成                             │
│   • 历史/文化背景补充                         │
│   延迟: 2~5s | 云端推理                      │
│                                             │
└─────────────────────────────────────────────┘
```

---

### 关键决策：VLM 跑在车端还是云端？

```
车端 VLM (4B 级别):
  ✅ 无需网络，隧道/地库也能用
  ✅ 隐私好（图片不上传）
  ❌ 算力有限，识别能力受限
  ❌ 知识库小，可能认不出小众景点

云端 VLM (大模型):
  ✅ 识别能力强，知识库丰富
  ✅ 能认出具体景点名称
  ❌ 需要网络，无信号时不可用
  ❌ 图片上传有隐私顾虑
  ❌ 延迟 2~5 秒

推荐: 混合方案
  有网络 → 云端大模型（回答更准确、更丰富）
  无网络 → 车端 4B VLM（基础识别 + GPS POI 兜底）
```

---

### 各摄像头在此场景中的角色

| 摄像头 | 角色 | 具体用途 |
|--------|------|---------|
| FWC | 主力感知 | 前方地标/天气/远处场景/景点建筑 |
| SC_FL | 左侧感知 | "左边那个是什么" / 左侧 POI |
| SC_FR | 右侧感知 | "右边的河/楼" / 右侧 POI |
| SC_RL | 左后感知 | "刚才经过的是什么"（短时回看） |
| SC_RR | 右后感知 | 同上 |
| SVC | 不参与 | 像素密度低+畸变大，不适合识别/闲聊 |

---

### 用户问题 → 摄像头路由逻辑

```
语义关键词映射:

  "前面/前方/那个" → FWC
  "左边/左侧/驾驶侧" → SC_FL
  "右边/右侧/副驾侧" → SC_FR
  "旁边" → SC_FL + SC_FR（两侧都看）
  "后面/刚才经过的" → SC_RL 或 SC_RR
  "周围/这是哪" → FWC + SC_FL + SC_FR（多图）
  无方向指示 → 默认 FWC
```

---

### 一句话总结

这组功能需要 **FWC + 4路SC 配合**（SVC 不参与），模型上需要 **CV 小模型处理安全实时任务 + VLM 处理语义理解和 POI 问答**，VLM 建议车云混合部署。核心是根据用户问题中的方向词，路由到对应摄像头取图再送模型分析。
