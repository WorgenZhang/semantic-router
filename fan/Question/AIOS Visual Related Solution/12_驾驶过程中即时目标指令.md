## ADAS 驾驶用户指示：摄像头 + 模型方案

---

### 功能定义

```
用户通过自然语言描述一个视觉目标或行为规则
系统需要:
  1. 理解用户说的是什么（语义理解）
  2. 从摄像头画面中找到对应目标（视觉定位）
  3. 执行相应驾驶动作（规划控制）

三种类型:
  A. 即时目标指令: "在那栋蓝色玻璃大楼前面停车"
  B. 即时跟随指令: "跟着前面那辆红色的车"
  C. 长期规则学习: "以后这条路下班时段都走最右道"
```

---

### 与传统 ADAS 的关键区别

```
传统 ADAS:
  → 识别所有车辆/行人/车道线（无差别感知）
  → 按固定规则决策（保持车道/跟车/限速）

用户指示 ADAS:
  → 需要从众多目标中找出"用户说的那个"（选择性注意）
  → 需要理解开放词汇描述（"蓝色玻璃大楼"/"那个老人"）
  → 需要将自然语言映射到视觉目标
  → 这是 VLM 的核心价值场景 ✅
```

---

### 功能 A：即时目标指令

#### "Stop in front of that blue glass building"

```
处理流程:

  用户语音 → "在那栋蓝色玻璃大楼前面停车"
       ↓
  LLM 语义解析:
    目标: building
    属性: blue, glass
    动作: stop
    空间关系: in front of
       ↓
  视觉搜索 (需要 VLM):
    从 FWC 画面中找到 "蓝色玻璃大楼"
    可能前方有多栋建筑 → 哪栋是蓝色玻璃的？
       ↓
  定位 + 测距:
    目标建筑在画面中的位置 → 估算距离
    规划减速 → 在其正前方停车
```

#### 为什么必须用 VLM

```
CV 小模型能做:
  ✅ 检测"建筑物"（通用目标检测）
  ❌ 区分"蓝色玻璃建筑" vs "灰色混凝土建筑" vs "红砖建筑"
  ❌ 理解"那栋"（指代消解 — 用户指的哪栋？）

VLM 能做:
  ✅ 开放词汇视觉定位 (Open-Vocabulary Grounding)
  ✅ 给定文本描述 → 在图像中框出对应目标
  ✅ 理解属性组合: "蓝色" + "玻璃" + "大楼"
  ✅ 区分多个候选目标中哪个最匹配
```

#### 更多例子

```
"在那家星巴克旁边停"
  → 需要识别具体品牌门店（Logo + 店面特征）

"让那个推婴儿车的人先过"
  → 需要从多个行人中找到"推婴儿车的"那个

"别跟太近那辆大卡车"
  → 需要区分"大卡车"和普通小车

"在老人过完马路之后再走"
  → 需要识别"老人"（年龄判断）+ 追踪其过马路状态
```

### 功能 B：即时跟随指令

#### "Follow the red car ahead"

```
处理流程:

  用户语音 → "跟着前面那辆红色的车"
       ↓
  VLM 目标锁定:
    从 FWC 画面中找到"红色的车"
    前方可能有多辆车 → 哪辆是红色的？
    锁定目标 ID
       ↓
  CV 目标追踪 (持续):
    VLM 只负责第一帧找到目标
    后续帧用 CV tracker 持续追踪（省算力）
    即使目标变道/被遮挡，追踪器保持锁定
       ↓
  驾驶决策:
    保持与目标车辆的跟随距离
    目标变道 → 自车跟随变道
    目标停车 → 自车停车
```

#### VLM + CV 协作模式

```
┌───────────────────────────────────────────────┐
│       VLM 找目标 + CV 追踪目标                  │
│                                               │
│  第 0 帧 (VLM):                                │
│    输入: FWC 画面 + "红色的车"                  │
│    输出: 目标框 [x1,y1,x2,y2] + 目标 ID        │
│    延迟: 1~2s（可以接受，只跑一次）             │
│                                               │
│  第 1~N 帧 (CV Tracker):                       │
│    输入: 连续帧 + 上一帧目标位置               │
│    输出: 当前帧目标位置                         │
│    延迟: <30ms（实时追踪）                      │
│    模型: DeepSORT / ByteTrack 级别             │
│                                               │
│  异常处理:                                      │
│    目标丢失（遮挡/出画面）→ 重新调用 VLM 搜索   │
│    用户说"不是那辆，是旁边那辆" → VLM 重选      │
│                                               │
└───────────────────────────────────────────────┘
```

### 功能 C：长期规则学习

#### "以后这条路下班时段都走最右道"

```
这个功能不依赖实时视觉识别，而是:

  Step 1: 语义理解 (LLM)
    解析规则:
      条件: 这条路 + 下班时段 (17:00-19:00)
      动作: 走最右道
    
  Step 2: 规则存储
    绑定到: GPS 路段 + 时间段 + 车道偏好
    存入用户驾驶偏好数据库

  Step 3: 触发执行 (未来某天)
    GPS 识别到进入该路段
    + 当前时间在 17:00-19:00
    → 自动规划到最右车道
    → 提前变道

  需要摄像头做什么:
    → 识别当前在第几车道（CV 车道线检测）
    → 确认最右道可用（CV 目标检测）
    → 安全变道（CV 常规 ADAS 感知）
```

#### 更多长期规则示例

```
"经过学校那段路限速 30"
  → GPS 路段 + 限速覆写规则
  → 摄像头: 不特别需要（靠 GPS 触发）

"这个路口右转总是有人闯红灯，小心点"
  → GPS 路口 + 提高右侧行人检测灵敏度
  → 摄像头: SC_FR 加强行人检测

"上次在这停车刮了，以后别停这种窄位"
  → 停车场 + 车位宽度阈值提高
  → 摄像头: SC + SVC 车位宽度估算
```

### 摄像头方案

#### 即时指令（功能 A & B）：FWC 为绝对主力

```
为什么是 FWC:
  → 用户说的目标 90% 在正前方
    "前面的红车"/"那栋楼"/"那个老人"
  → 8MP 高分辨率，远处目标也能看清属性
  → 画面最像"驾驶员视角"，用户的"那个"通常指驾驶员能看到的

其他摄像头的角色:
  SC_FL/FR: 用户说"旁边的"/"右边那辆"时
  RVC: 用户说"后面跟着的那辆"时（少见）
  SVC: 不参与目标识别（分辨率+畸变不适合属性识别）
```

#### 各场景摄像头分配

| 用户指令举例 | 主摄像头 | 辅助 |
|-------------|---------|------|
| "前面那栋蓝色大楼" | FWC | - |
| "跟着前面红色的车" | FWC | - |
| "让那个老人先过" | FWC | SC_FL/FR |
| "右边那辆白色 SUV" | SC_FR | FWC |
| "旁边车道的卡车" | SC_FL 或 SC_FR | FWC |
| "后面一直跟着的黑色车" | RVC | SC_RL/RR |
| "那个骑电动车的" | FWC | SC_FL/FR |
| "停在那棵大树旁边" | FWC | SC |

### 模型架构

```
┌──────────────────────────────────────────────────────────────┐
│          ADAS 用户指示 - 模型分层架构                          │
│                                                              │
│  [Layer 1: 语音理解] — LLM (车端/云端)                        │
│                                                              │
│   输入: 用户语音转文本                                         │
│   输出: 结构化指令                                            │
│     {                                                        │
│       type: "follow" / "stop_at" / "avoid" / "rule",         │
│       target: "red car" / "glass building" / "old person",   │
│       spatial: "ahead" / "right" / "in_front_of",            │
│       action: "follow" / "stop" / "slow_down"                │
│     }                                                        │
│   延迟: 0.5~1s                                               │
│                                                              │
│  [Layer 2: 视觉定位] — VLM (车端 4B 或 云端)                  │
│                                                              │
│   输入: 摄像头画面 + 目标描述文本                              │
│   任务: Open-Vocabulary Grounding (开放词汇视觉定位)          │
│   输出: 目标在画面中的位置框 [x1,y1,x2,y2]                   │
│                                                              │
│   具体能力:                                                   │
│   • "blue glass building" → 框出蓝色玻璃大楼                 │
│   • "red car ahead" → 从多辆车中框出红色那辆                 │
│   • "old person" → 从行人中找到老年人                         │
│   • "Starbucks" → 识别特定品牌门店                           │
│                                                              │
│   延迟: 1~2s (只在目标锁定时调用一次)                         │
│   算力: 10~30 TOPS                                           │
│                                                              │
│  [Layer 3: 目标追踪] — CV (车端实时)                           │
│                                                              │
│   输入: VLM 给出的初始目标框 + 连续视频帧                     │
│   输出: 每帧目标最新位置                                      │
│   模型: DeepSORT / ByteTrack / 轻量 Tracker                  │
│   延迟: <30ms (每帧实时)                                     │
│   算力: ~1 TOPS                                              │
│                                                              │
│  [Layer 4: 常规 ADAS 感知] — CV (车端实时，始终运行)           │
│                                                              │
│   车道线检测 / 障碍物检测 / 交通灯 / 限速牌                   │
│   → 为执行用户指令提供安全保障                                │
│   算力: ~8-10 TOPS                                           │
│                                                              │
│  [Layer 5: 规则存储 & 触发] — 数据库 + GPS                    │
│                                                              │
│   长期规则: GPS 路段 + 时间 + 偏好 → 自动触发                │
│   无额外算力需求                                              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### VLM 在此场景中的不可替代性

```
这是整车场景中 VLM 最核心的用途之一

为什么 CV 做不了:
  
  "红色的车":
    CV 目标检测 → 能检测出所有"车"
    但颜色属性判断 + "哪辆是红的" → 需要属性理解
    → 可以用 CV + 颜色分类勉强做

  "蓝色玻璃大楼":
    CV 目标检测 → 能检测"建筑物"
    但 "蓝色" + "玻璃" + "大楼" 三属性组合 → CV 类别爆炸
    → 不可能为每种属性组合训练分类器

  "推婴儿车的老人":
    CV → 能检测"人"和"婴儿车"
    但 "推" 这个动作关系 + "老人" 年龄属性 → CV 做不了
    → 需要 VLM 理解视觉关系

  "那个穿外卖服骑电动车的":
    CV → 检测"人"、"电动车"
    但 "穿外卖服" + "骑" + 人车关联 → 需要语义理解
    → VLM 的核心能力

核心差异:
  CV = 封闭词汇检测（只能识别训练过的类别）
  VLM = 开放词汇理解（可以理解任意自然语言描述）
```

### 技术挑战 & 解决方案

#### 挑战 1：VLM 延迟 vs 驾驶实时性

```
问题:
  VLM 推理 1~2s，但驾驶不能等 2 秒

解决:
  VLM 只用于"找到目标"（一次性），不用于"持续追踪"
  
  时间线:
  t=0s:    用户说"跟着前面那辆红色的车"
  t=0.5s:  语音识别 + LLM 解析完毕
  t=1.5s:  VLM 在 FWC 画面中定位到红色车 → 输出框
  t=1.5s+: CV Tracker 接管，每帧实时追踪（<30ms）
  
  用户感知: 说完话 1.5 秒后系统锁定目标 ← 可接受
```

#### 挑战 2：目标歧义

```
问题:
  前方有 3 辆红色的车，用户指的是哪辆？

解决方案:
  1. 空间线索: "前面的" → 最近的那辆
  2. 大小线索: "那辆大的红车" → 最大的
  3. 多轮确认: 系统问 "您是指最近的那辆红色轿车吗？"
  4. 手指指向: 结合舱内手势（用户指向某方向）+ 摄像头
```

#### 挑战 3：目标消失/变化

```
问题:
  跟随的红色车转弯消失了 / 被其他车遮挡了

解决:
  短暂遮挡 (<2s): Tracker 预测位置，等待重新出现
  长时间丢失 (>3s): 
    → 重新调用 VLM 在当前画面中搜索
    → 找不到 → 语音提示 "目标车辆已离开视野，是否取消跟随？"
```

#### 挑战 4：长期规则的边界情况

```
"以后这条路下班时段都走最右道"

边界情况:
  → 最右道有事故/施工怎么办？
  → 答: 安全层否决，临时走其他道，语音提示

  → "下班时段"具体是几点？
  → 答: LLM 结合用户画像推断（或追问确认），默认 17:00-19:00

  → "这条路"是哪条路？
  → 答: 当前 GPS 路段，记录路段 ID

  → 用户改主意了怎么办？
  → 答: "取消这个规则" / "改成走中间道"
```

### 摄像头最终方案

| 功能场景 | 主摄像头 | 辅助 | 模型 |
|---------|---------|------|------|
| 前方目标定位 | FWC (8MP) | - | VLM grounding |
| 侧方目标定位 | SC_FL/FR | FWC | VLM grounding |
| 后方目标定位 | RVC | SC_RL/RR | VLM grounding |
| 目标持续追踪 | FWC/SC (同一路) | - | CV Tracker |
| 车道识别（规则执行） | FWC | - | CV 车道线检测 |
| 安全保障（全程） | 全部摄像头 | - | CV ADAS 感知 |

### 与其他场景对比：为什么这个场景 VLM 不可替代

```
场景对比:

  路牌识别: CV 够了（标准化目标，封闭类别）
  停车限制: CV + OCR 够了（固定文字关键词）
  哨兵模式: CV 够了（只需检测有没有人）
  天气识别: CV 够了（几个固定类别分类）

  用户指示目标: ❌ CV 不够，✅ 必须 VLM
    → 目标描述是开放式的（无法穷举训练）
    → 属性组合无限（颜色+材质+类型+动作+关系）
    → 需要语言-视觉对齐能力
    → 这是 VLM 的设计初衷

这个场景 = VLM 在 ADAS 中最强 justification
```

### 算力预算

```
VLM 视觉定位 (按需触发):
  触发频率: 用户每次下达新指令时（偶发）
  单次算力: 10~30 TOPS × 1~2s
  不占持续算力

CV 目标追踪 (持续运行):
  追踪锁定目标: ~1 TOPS
  持续运行直到任务结束

常规 ADAS CV (始终运行):
  车道线+障碍物+交通灯: ~8-10 TOPS

LLM 语义理解 (按需):
  车端小模型: ~5 TOPS × 0.5s
  或云端调用: 无车端算力

总计:
  常态: ~10 TOPS (CV ADAS + Tracker)
  指令触发峰值: +10~30 TOPS (VLM，持续 1~2s)
```

---

### 一句话总结

ADAS 用户指示是 **VLM 在整车中最不可替代的场景**——用户用开放自然语言描述目标，系统必须"看懂"画面并找到对应物体。摄像头以 **FWC 为绝对主力**（目标基本在前方），模型架构为 **LLM 理解意图 → VLM 视觉定位（一次性）→ CV Tracker 持续追踪（实时）**三级流水线。长期规则不依赖视觉，靠 GPS + 时间触发即可。
