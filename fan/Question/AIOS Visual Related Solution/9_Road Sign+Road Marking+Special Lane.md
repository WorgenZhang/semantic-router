## 道路标识/特殊车道/区域识别：摄像头 + 模型方案

---

### 三类目标的物理特征

```
Road Sign & Marking (路牌 & 地面标线):
  → 路牌: 前方高处或路侧，反光材质，标准化图形
  → 标线: 地面，白色/黄色，各种箭头和文字

Special Lane (特殊车道):
  → 地面文字标识（"公交专用"、"ETC"）
  → 头顶LED可变信息牌（潮汐车道方向指示）
  → 路侧时间限制牌（"7:00-9:00 禁止通行"）

Zone/Area (区域):
  → 路侧标志牌（学校区域标志、事故警告）
  → 地面标识（人行横道斑马线）
  → 环境特征（减速带、彩色路面、闪烁警示灯）
```

---

### 摄像头需求分析

#### 核心结论：FWC 为绝对主力，FTC 长焦辅助

```
┌──────────────────────────────────────────────────────┐
│                各目标的视觉位置分布                     │
│                                                      │
│         路牌 ← 前上方 (20~100m)                       │
│         LED牌 ← 头顶 (10~50m)                        │
│         地面标线 ← 正前方地面 (5~50m)                  │
│         区域标志 ← 路侧 (20~80m)                      │
│         斑马线 ← 正前方地面 (10~30m)                   │
│                                                      │
│              全部在 FWC 的 H120°×V66° 范围内           │
└──────────────────────────────────────────────────────┘
```

---

### 各摄像头角色

| 摄像头 | 角色 | 原因 |
|--------|------|------|
| FWC (8MP, H120°) | **主力** | 前方高分辨率，路牌/标线/区域标志全覆盖 |
| FTC (H45°) | **辅助** | 长焦窄角，远距离路牌文字识别（100m+） |
| SC_FL / SC_FR | 补充 | 路侧极偏位置的标志牌（非典型场景） |
| SVC | 不参与 | 畸变大、像素密度低，无法识别文字 |
| RVC | 不参与 | 朝后看，与前方路况无关 |

---

### 为什么 FWC + FTC 组合最优

```
FWC (H120°, 8MP):
  → 宽视角覆盖: 路牌可能在路左侧、右侧、正上方
  → 近中距离: 5~50m 内标线和标志清晰可辨
  → 像素密度: 3840 ÷ 120° = 32 px/°
  → 50m 外的路牌 (宽60cm ≈ 0.7°): 0.7° × 32 = 22px ← 勉强可识别

FTC (H45°, 长焦):
  → 窄视角但像素更集中
  → 像素密度更高，远距离文字可读
  → 100m 外的路牌: 在 FTC 中占更多像素 ← 清晰可读
  → 特别适合: 高速公路上提前 200m 读取限速牌

两者配合:
  FTC: 远距离提前发现 (100~200m) → "前方有限速牌"
  FWC: 中近距离确认细节 (10~50m) → "限速60，学校区域"
```

---

### 各识别目标详细方案

#### 1. Road Sign（路牌）

```
目标: 限速牌/禁止牌/指示牌/警告牌

摄像头: FWC + FTC
  FTC: 远距离粗检测（有个牌子）
  FWC: 中距离精确识别（什么牌子，写的什么）

模型: CV 小模型 ✅ (不需要 VLM)
  → 检测: 路牌定位（YOLO 级别）
  → 分类: 标准交通标志分类（100+ 类别）
  → OCR: 读取非标准牌面文字（如"前方施工"）

为什么不需要 VLM:
  → 交通标志是标准化的（国标 GB 5768）
  → 形状+颜色+图案 → 直接分类，无需语义理解
  → 实时性要求高（要在车到达之前读完）
  → 延迟要求: <100ms

模型规格:
  检测+分类: ~2 TOPS
  OCR（文字牌）: ~1 TOPS
  总计: ~3 TOPS
```

#### 2. Road Marking（地面标线）

```
目标: 车道线/箭头/文字标线/停止线/减速标线

摄像头: FWC 为主
  → 地面标线在 FWC 画面下半部分
  → V66° 垂直视角，下方 33° 覆盖 5~30m 前方路面

模型: CV 小模型 ✅
  → 语义分割: 逐像素分类（车道线/箭头/文字/停止线）
  → 或实例检测: 框出每个标线并分类

  地面文字识别（"公交专用"、"ETC"）:
  → 小型 OCR 模型

模型规格:
  分割/检测: ~3 TOPS
  地面 OCR: ~1 TOPS
```

#### 3. Special Lane（特殊车道）

```
目标:
  公交专用道 → 地面文字 "公交专用" + 黄色标线
  潮汐车道 → 头顶 LED 方向指示 (红×/绿↓)
  可变车道 → 锯齿形标线 + 指示牌
  限时车道 → 路侧时间牌 ("7:00-9:00 公交专用")
  ETC车道 → 头顶 "ETC" 标识 + 地面标线

摄像头: FWC (主) + FTC (远距离预读)

模型: CV + 轻量 OCR
  ├─ 标线检测: 识别锯齿线、黄色专用道线（CV）
  ├─ LED 指示识别: 红色×/绿色↓ 状态分类（CV）
  ├─ 文字识别: "公交专用"、时间文字（OCR）
  └─ 时间解析: "7:00-9:00" → 判断当前是否在限制时段（规则引擎）

是否需要 VLM？
  大部分不需要 ← 标准化标识，CV + OCR 够了
  
  可能需要 VLM 的场景:
  → 非标准指示（临时贴纸、手写提示）
  → 复杂组合判断（多个牌子组合含义）
  → 但这些可以 CV 检测 + 云端 VLM 确认
```

#### 4. Zone/Area（区域识别）

```
目标:
  学校区域 → 学校标志牌 + 减速带 + 彩色路面 + 限速30
  人行横道 → 斑马线 + 行人信号灯 + 让行标志
  事故现场 → 三角警告牌 + 闪烁警示灯 + 异常停车 + 碎片

摄像头: FWC (主) + SC_FL/SC_FR (辅助)
  FWC: 识别前方区域标志和环境特征
  SC: 补充感知路侧细节（侧方摆放的三角牌）

模型: CV 为主，VLM 辅助

  学校区域:
    CV ✅ → 标志牌识别 + 限速牌 + 减速带检测
    规则: 多个特征同时出现 → 判定为学校区域

  人行横道:
    CV ✅ → 斑马线语义分割 + 行人检测
    纯 CV 可完成

  事故现场:
    CV + VLM △ → 复杂场景
    CV: 检测三角牌、异常停车、碎片
    VLM（可选）: 理解复杂事故场景布局
    
    为什么事故现场可能需要 VLM:
    → 事故形态千变万化，不是标准化场景
    → 需要判断: 碎片范围/可通行路线/严重程度
    → CV 能检测单个目标，但理解"整体是个事故"需要语义
```

### 模型总结

```
┌─────────────────────────────────────────────────────────┐
│                    模型架构                               │
│                                                         │
│  [车端实时 - CV 模型]                                    │
│                                                         │
│   路牌检测+分类        ─── ~2 TOPS ─── <50ms            │
│   地面标线分割         ─── ~3 TOPS ─── <50ms            │
│   OCR (文字识别)       ─── ~1 TOPS ─── <100ms           │
│   LED信号状态分类      ─── ~0.5 TOPS── <30ms            │
│   行人/车辆检测        ─── ~2 TOPS ─── <50ms            │
│   ─────────────────────────────────────                 │
│   总计:                    ~8-10 TOPS                    │
│                                                         │
│  [车端/云端 - VLM] (非安全场景，按需调用)                  │
│                                                         │
│   非标准路牌理解       ─── 触发式 ─── 1~3s              │
│   复杂事故场景判断     ─── 触发式 ─── 1~3s              │
│   组合标志语义解读     ─── 触发式 ─── 1~3s              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 为什么这些场景主要用 CV 不用 VLM

```
原因 1: 标准化
  交通标志/标线全部有国标（GB 5768）
  → 形状、颜色、尺寸都是固定的
  → 训练一个分类模型就够了，不需要"理解"

原因 2: 实时性
  限速牌必须在车到达之前识别完
  → 100km/h 时，100m 只有 3.6 秒
  → VLM 推理 1~3 秒 → 可能来不及
  → CV <50ms → 绰绰有余

原因 3: 确定性
  安全场景需要确定性输出
  → CV: "这是限速60牌" → 100%确定性
  → VLM: "这看起来像个限速牌" → 有幻觉风险

原因 4: 算力
  这些检测需要每帧都跑（30fps）
  → 30fps × VLM = 不可能
  → 30fps × CV 小模型 = 完全可行
```

### 距离 vs 摄像头选择

```
距离轴:

  200m        100m         50m         10m        0m
   |───────────|────────────|───────────|──────────|
   
   ←── FTC 长焦 ──→
         (提前发现)
   
              ←────── FWC 主摄 ──────────────→
                    (确认识别 + 持续追踪)

                                    ←─ SC 辅助 ─→
                                      (路侧近距离)

路牌识别流程:
  200m: FTC 检测到"前方有标志牌" (粗框)
  100m: FTC 读取文字/图案 (确认类型)
   50m: FWC 精确识别 (多重确认)
   10m: 标志牌进入正上方 → 跟踪结束
```

### 最终方案

| 目标 | 主摄像头 | 辅助 | 模型 | VLM? |
|------|---------|------|------|------|
| 路牌 (标准) | FWC + FTC | - | CV 分类 | 不需要 |
| 路牌 (非标准文字) | FWC | - | CV + OCR | 偶尔需要 |
| 地面标线 | FWC | - | CV 分割 | 不需要 |
| 公交/ETC车道 | FWC | - | CV + OCR | 不需要 |
| 潮汐车道 LED | FWC + FTC | - | CV 分类 | 不需要 |
| 限时车道 | FWC + FTC | - | OCR + 规则 | 不需要 |
| 学校区域 | FWC | SC | CV 多特征融合 | 不需要 |
| 人行横道 | FWC | - | CV 分割+检测 | 不需要 |
| 事故现场 | FWC | SC_FL/FR | CV 检测 | 可选辅助 |

---

### 一句话总结

路标/车道/区域识别几乎全靠 **FWC + FTC 前视摄像头组合 + CV 小模型**搞定，因为目标都在前方、标准化程度高、实时性要求严格。VLM 只在极少数非标准场景（临时路牌文字、复杂事故判断）作为补充，且可以延迟触发。核心算力预算约 8~10 TOPS。
