## 多 CV 模型同时触发的优先级判定

### 核心原则：安全 > 法规 > 功能

---

### 典型优先级分层

```
Priority 0 (最高): 安全相关
  → 疲劳识别（闭眼/打哈欠）
  → 分心检测（长时间视线偏离）
  
Priority 1: 法规合规
  → 打电话识别（违反交规）
  → 未系安全带

Priority 2: 功能交互
  → 手势识别（调音量、接挂电话）
  → 儿童识别（儿童锁联动）

Priority 3 (最低): 状态感知
  → 乘员计数
  → 坐姿识别
```

---

### 你举的例子：手势 + 打电话同时发生

```
场景: 驾驶员正在打电话，同时举手做了一个"OK"手势

系统判定:
  ├─ 打电话识别触发 → Priority 1 (法规)
  └─ 手势识别触发   → Priority 2 (功能)

结果: 打电话优先
  → 执行: 弹出"请勿接打电话"安全提醒
  → 抑制: 手势控制功能不响应

为什么？
  驾驶员打电话时的手部动作容易被误识别为功能手势
  即使是真手势，安全提醒也不应该被打断
```

---

### 常见冲突场景与仲裁逻辑

| 同时触发 | 优先响应 | 被抑制 | 理由 |
|----------|---------|--------|------|
| 疲劳 + 打电话 | 疲劳 | 打电话提醒延后 | 瞌睡比打电话危险 |
| 疲劳 + 手势 | 疲劳 | 手势不响应 | 闭眼状态下的"手势"大概率是误检 |
| 打电话 + 手势 | 打电话 | 手势不响应 | 举手到耳边容易误触手势 |
| 儿童识别 + 手势 | 都响应 | 无冲突 | 不同区域，互不影响 |
| 分心 + 手势 | 分心 | 手势不响应 | 视线偏离时手势无意义 |

---

### 仲裁机制的实现方式

```
方案 1: 优先级抢占（Preemptive）

  高优先级事件直接打断低优先级
  
  if (fatigue_detected) {
      suppress(gesture);
      suppress(phone_call_warning);  // 延后，不丢弃
      execute(fatigue_alert);         // 立刻报警
  }

方案 2: 状态机互斥（State Lock）

  进入某个高优先级状态后，锁定低优先级响应
  
  [正常] → 检测到打电话 → [电话警告状态]
                              │
                              └→ 此状态下手势识别输出被屏蔽
                              └→ 直到"打电话"状态退出

方案 3: 时间窗口仲裁（Time-window Arbitration）

  同一时间窗口（如 500ms）内多个触发，只响应最高优先级
  
  ┌─── 500ms 窗口 ───┐
  │ 手势 @t1         │
  │ 打电话 @t2       │  → 窗口结束时，选 Priority 最高的
  │ (疲劳未触发)      │
  └──────────────────┘
  → 输出: 打电话警告
```

---

### 实际系统中通常怎么做

```
                    ┌─────────────┐
  疲劳模型输出 ────→│             │
  打电话模型输出 ──→│  优先级仲裁  │──→ 最终执行动作
  手势模型输出 ────→│  (Arbiter)  │
  儿童模型输出 ────→│             │
                    └─────────────┘

Arbiter 逻辑:
  1. 收集所有模型在当前帧的输出
  2. 过滤置信度 < 阈值的（减少误触发冲突）
  3. 按优先级排序
  4. 最高优先级执行，低优先级根据策略 抑制/延后/并行
```

---

### 额外考虑：不是所有冲突都要"二选一"

```
可以并行的:
  儿童识别 + 手势识别 → 两个不冲突，同时响应
  乘员计数 + 任何识别 → 计数是后台统计，不影响前台交互

必须互斥的:
  疲劳 + 手势 → 疲劳时不应响应手势（可能是无意识动作）
  打电话 + 手势 → 举手动作语义冲突
```

---

### 一句话总结

多模型同时触发时，由一个中央仲裁模块按**"安全 > 法规 > 功能 > 状态"**的优先级链决策，高优先级抢占或抑制低优先级，同优先级内按置信度或时序选择。不冲突的检测结果可以并行输出。
