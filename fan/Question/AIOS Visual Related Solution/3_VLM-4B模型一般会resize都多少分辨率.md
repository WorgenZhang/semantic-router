## VLM-4B 模型典型输入分辨率

### 主流 4B 级别 VLM 的 resize 目标

| 模型 | 参数量 | 输入分辨率 | 说明 |
|------|--------|-----------|------|
| InternVL2-4B | 4B | 448×448 (单tile) | 支持动态分辨率，最多 12 tiles |
| Phi-3-Vision | 4.2B | 336×336 (单tile) | 最多切成 2×2=4 tiles |
| PaliGemma-3B | 3B | 224×224 或 448×448 | 可选配置 |
| Qwen2-VL (小) | ~4B | 动态，最长边 1280 | 按 28px patch 切分 |

---

### 通常的处理方式

```
原始图像 (例如 3840×2160)
       ↓
等比缩放到模型最大输入范围 (通常 448~768px 长边)
       ↓
切成多个 tile (每个 224×224 或 336×336 或 448×448)
       ↓
每个 tile 经过 Vision Encoder 提取特征
```

---

### 4B 模型的典型范围

```
单 tile 模式:   448×448（最常见）
多 tile 模式:   等效覆盖约 896×896 ~ 1344×1344

实际有效分辨率 ≈ 448 ~ 1344 px（取决于 tile 数量上限）
```

---

### 对你们场景的意义

```
FWC 原始: 3840×2160 (8MP)
SC 原始:  1960×1536 (3MP)

VLM-4B 实际使用: 最多等效 ~1000px 级别

所以:
  8MP → 被 resize 到 ~1000px（压缩了约 3~4 倍）
  3MP → 被 resize 到 ~1000px（压缩了约 1.5~2 倍）
```

这也是为什么之前说"适度降分辨率对 VLM 影响不大"——如果从 3MP 降到 1.5MP，最终送进模型时差距不会太大。但如果降到远低于模型有效分辨率（比如低于 1000px 长边），就会开始丢失细节。

## 多 Tile 模式 图解

### 核心问题

```
VLM 的 Vision Encoder 一次只能"看"一小块图（比如 448×448）
但输入图像可能很大（比如 1960×1536）

怎么办？→ 把大图切成多个小块（tile），每块单独处理
```

---

### 单 Tile 模式（简单粗暴）

```
原始图像 1960×1536
        ↓ 直接缩小
   ┌──────────┐
   │          │
   │ 448×448  │  ← 整张图压缩到一个 tile 里
   │          │
   └──────────┘

问题: 远处的小路牌、小行人全被压没了
```

---

### 多 Tile 模式（保留细节）

以 InternVL2-4B 为例，假设最多支持 6 个 tile：

```
原始图像 1960×1536
        ↓ 切分成 2×3 = 6 块

┌─────────┬─────────┐
│ Tile 1  │ Tile 2  │
│ 448×448 │ 448×448 │
├─────────┼─────────┤
│ Tile 3  │ Tile 4  │
│ 448×448 │ 448×448 │
├─────────┼─────────┤
│ Tile 5  │ Tile 6  │
│ 448×448 │ 448×448 │
└─────────┴─────────┘

等效分辨率: 896×1344（2列×3行，每块448px）
```

再加一个缩略图 tile 看全局：

```
┌─────────┬─────────┐
│ Tile 1  │ Tile 2  │         ┌──────────┐
├─────────┼─────────┤    +    │ Tile 7   │  ← 全图缩小到 448×448
│ Tile 3  │ Tile 4  │         │ (缩略图) │     让模型理解全局布局
├─────────┼─────────┤         └──────────┘
│ Tile 5  │ Tile 6  │
└─────────┴─────────┘
   局部细节 tiles              全局概览 tile
```

---

### 具体例子：FWC 图像 3840×2160 送入 4B VLM

```
Step 1: 选择切分方案

  3840×2160 的宽高比 ≈ 16:9
  模型选择最接近的 tile 排布: 4×2 = 8 tiles

Step 2: 每个 tile 覆盖的原始区域

  原图按 4×2 切分:
  每块覆盖: 960×1080 像素的原始区域
  每块缩放到: 448×448 送入 encoder

  ┌──────┬──────┬──────┬──────┐
  │Tile1 │Tile2 │Tile3 │Tile4 │  ← 上半部分（天空+远方道路）
  │960×  │960×  │960×  │960×  │
  │1080  │1080  │1080  │1080  │
  ├──────┼──────┼──────┼──────┤
  │Tile5 │Tile6 │Tile7 │Tile8 │  ← 下半部分（近处路面+车辆）
  │      │      │      │      │
  └──────┴──────┴──────┴──────┘

Step 3: 加上 1 个全局缩略图

  总共 9 个 tiles → 每个 tile 生成 256 个 token
  → 送入 LLM 的视觉 token 数 = 9 × 256 = 2304 个
```

---

### 为什么多 tile 能保留细节

```
单 tile:
  200m 外的行人在原图中占 ~20px
  缩放到 448×448 后 → 只剩 ~2px → 模型看不清

多 tile (4×2):
  那个行人落在某一个 tile 里
  这个 tile 把 960×1080 区域放大到 448×448
  行人从 20px → ~9px → 模型勉强能识别
```

---

### 不同 tile 数量 vs 等效分辨率

| tile 排布 | tile 总数 | 等效分辨率 | 视觉 token 数 | 计算开销 |
|-----------|----------|-----------|--------------|---------|
| 1×1 | 1 | 448×448 | 256 | 最低 |
| 2×2 | 4 | 896×896 | 1024 | 中等 |
| 3×2 | 6 | 1344×896 | 1536 | 较高 |
| 4×3 | 12 | 1792×1344 | 3072 | 最高（4B模型上限） |

---

### 一句话总结

多 tile = 把大图切成小块分别看清细节，再加一张缩略图看懂全局。tile 越多，模型看到的细节越多，但计算成本也越高。4B 模型通常限制在 6~12 个 tile，等效分辨率约 900~1300px。

## 20px 的来源

20px 说的不是 tile 尺寸，而是**200m 外的行人在原始全图中占多少像素**。

---

### 计算过程

```
已知:
  FWC 分辨率: 3840×2160
  FWC 垂直 FOV: 66°
  行人身高: ~1.7m
  行人距离: 200m

Step 1: 行人在画面中占多少度？

  角度 = arctan(1.7 / 200) ≈ 0.49°

Step 2: 每度对应多少像素？

  垂直方向: 2160px ÷ 66° ≈ 32.7 px/°

Step 3: 行人占多少像素？

  0.49° × 32.7 px/° ≈ 16px
  
  约等于 ~20px（取整估算）
```

---

### 所以那段话的完整逻辑是

```
行人在 200m 外
  → 在原图 3840×2160 中高约 16~20px     ← 这就是 20px 的含义
  → 如果整张图压到 448×448（单tile）
    缩放比 = 448 / 2160 ≈ 0.21
    行人高度 = 20 × 0.21 ≈ 4px           → 基本看不清

  → 如果用多 tile (4×2)，行人所在区域被单独切出
    那块 tile 覆盖 960×1080
    缩放比 = 448 / 1080 ≈ 0.41
    行人高度 = 20 × 0.41 ≈ 8~9px         → 勉强可识别
```

---

总结：20px 是"200m 远的行人在 FWC 原始 8MP 图像中的像素高度"，和 960×1080 没有直接关系，是两个独立的数。
