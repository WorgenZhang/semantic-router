# AIOS Visual Router - Scheduling 参数解读

## `npu_config`

| 参数                                        | 值                                       | 含义                                                                                                                       |
| ------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `max_concurrent_models: 1`                | NPU 同一时刻只能跑**1 个模型推理** | 硬件约束——NPU 不像 GPU 能并行多 kernel，必须串行调度                                                                     |
| `scheduling_strategy: "priority_preempt"` | 优先级抢占式调度                         | 高优先级任务可以打断低优先级正在执行的推理                                                                                 |
| `time_slice_ms: 30`                       | 每个模型一次最多占用 NPU**30ms**   | 类似 OS 时间片轮转，防止低优先级模型长期霸占 NPU，NPU 抢占粒度——一个模型最多跑 30ms 就必须检查是否有更高优先级任务要插队 |

## `priority_preemption`

| 参数                               | 含义                                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `safety_tier_preempts_all: true` | Safety 层级（priority 90-100）的任务可以**无条件抢占** 其他所有层级                                          |
| `min_execution_guarantee_ms: 10` | 即使被抢占，低优先级任务也保证至少跑完**10ms**——避免饥饿（starvation），确保低优模型不会永远拿不到推理机会 |

## `resource_conflict_resolution`

| 参数                            | 含义                                                                                                                        |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `same_backbone_shared: true`  | 多个 UC 共用同一个 backbone（如 `backbone_b`）时 **不算冲突**——因为 backbone 只需推理一次，多个 head 共享 feature |
| `vlm_async: true`             | VLM 推理走异步通道（可能 offload 到 CPU/云端），**不阻塞** NPU 上的 CV/ViT pipeline                                   |
| `max_pending_vlm_requests: 3` | 异步 VLM 队列最多积压**3 个请求**，超出则丢弃或降级——防止异步队列无限膨胀                                           |

## 核心设计思路

NPU 是稀缺的串行资源，通过「优先级抢占 + 时间片 + 最低保证」实现安全任务实时性和非安全任务活性的平衡；backbone 共享和 VLM 异步化则是减少冲突、提高吞吐的两个关键优化。
