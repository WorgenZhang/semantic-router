最近像 OpenClaw 爆火之后，
MaaS 这个词进入了大众的视野

哪里可以买 token？
哪里能接更多模型？
哪里能统一结算？📌

你在找的，就是 MaaS 模型即服务（Model-as-a-Service）。
所以 MaaS 它更像一种卖模型服务的方式。
就像有人把模型接入、额度、计费、稳定性这些事都整包好了，你来买 token 接入你的 agent 直接用。
GPU 负责生产 token，MaaS 负责输送 token。

但你真把系统打开看，
会发现后面其实是几层不同的东西。

1.最外面先是 API 网关。
API 网关不是 AI 时代才有的，
它是微服务时代就出现的老概念。
后端服务越来越多之后，
大家需要一个统一入口去做**鉴权、限流、租户、计费、协议转换和流量治理**。

2.到了 AI 时代，API 网关又往前走了一步，变成了 AI 网关。⚡你可以把它理解成 API 网关在 AI 时代的演进版。
只是它后面接的，不再只是普通微服务，
而是**模型 provider、推理服务、embedding、rerank、
moderation、tool services** 这些 AI 能力。
所以它除了传统 API 网关那套能力，
还要多做一层模型抽象、**统一 openai api 接口、
安全检查、fallback、token 限流、用量和成本观测**。

服务商内部，
通常不是一个大模型直接裸着对你开放。
更常见的是：前面先有一个 AI 网关，
把不同模型 provider，或者自建模型服务，
统一收口成一个接口。

对自建推理集群而言，
还会有推理网关，
继续把流量分到具体的 vLLM / SGLang 实例里。
它更靠近 serving，
它不太关心你买的是哪个套餐，
它更关心：
**这条请求现在该打到哪组实例，
哪边更闲，
哪边 prefix cache 命中率更高，
pd 分离下，prefill 和 decode 怎么调度**。

决定“这条请求该用哪个模型”的，
是模型路由。🎯
**快一点的？强一点的？便宜一点的？
还是 reasoning 更强的？要不要 fallback 到下一档**？

All in all：
MaaS，是卖服务的方式。
API 网关，管统一入口。
AI 网关，是 API 网关在 AI 时代的升级。
推理网关，管推理流量和实例调度。
模型路由，管更聪明的选择模型。
