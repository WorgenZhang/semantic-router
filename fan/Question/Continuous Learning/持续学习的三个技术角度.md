vLLM Semantic Router 的持续学习（Continuous Learning）机制是通过**数据闭环**实现的。这个闭环将运行时的路由决策、信号提取和用户反馈紧密结合，不断优化系统的准确性。

以下是从你提出的三个角度的详细技术原理解读：

### 1. Track which signals lead to better routing decisions (追踪有效信号)

**核心机制：Router Replay & Analytics**

系统不仅仅是在“做决定”，它还在“记笔记”。
*   **信号关联性记录**：每次路由请求，系统都会通过 `router_replay` 插件记录下完整的快照（Snapshot）：
    *   **Input**: 用户的原始 Query。
    *   **Extracted Signals**: 当时提取出的所有信号值（如：`keywords=["code"]`, `embedding_score=0.85`）。
    *   **Decision**: 最终走了哪条路由（如：`code_route`）。
    *   **Outcome**: 模型的响应时间、Token 消耗等。
*   **分析原理**：
    *   后台分析模块会统计**信号命中率（Signal Hit Rate）**。例如，如果发现只要 `math_keywords` 出现，用户对结果的接受率就很高，系统就会增加该信号在相关决策中的**隐式权重**。
    *   反之，如果某个 Embedding 信号频繁导致路由到了错误模型（后续被用户反馈差评），系统会标记该信号规则为“低质量”，建议管理员调整阈值（比如将 `threshold` 从 0.75 提高到 0.85）。

### 2. Collect user feedback to improve signal detection (收集反馈优化信号)

**核心机制：Explicit & Implicit Feedback Loop**

系统设计了专门的反馈通道，将“人的判断”注入到“机器的逻辑”中。
*   **显式反馈 (Explicit)**:
    *   用户可以通过 `/v1/feedback` 接口直接对某次对话点赞（👍）或点踩（👎）。
    *   **Mapping**: 如果用户对走 `quick_answer` 路由的结果点了踩，并备注“太简略”，系统会生成一条负样本数据：`{query: "...", routed_to: "quick_answer", feedback: "negative"}`。
*   **隐式反馈 (Implicit)**:
    *   通过后续对话推断。如果用户在得到答案后马上问“Are you sure?”或者“Rewrite this in Python”，这暗示之前的路由（可能走了通用闲聊路由）是失败的。
*   **信号校准 (Calibration)**:
    *   这些反馈数据会被用来**微调（Fine-tune）**或**重校准（Re-calibrate）**信号分类器。
    *   **例子**: 系统原本认为 "show me" 是通用词。但大量反馈显示 "show me" 后接代码需求时用户点赞率高。系统会自动建议将 "show me" 加入 `code_keywords` 列表，或者更新 Embedding 的参考样本库。

### 3. Build a self-learning system that gets smarter with use (构建自学习系统)

**核心机制：Online Learning / Adaptive Thresholds**

这是最高级的阶段，系统开始尝试“自我进化”。
*   **动态阈值调整 (Adaptive Thresholds)**:
    *   对于 `confidence_route` 或 `ratings_route`，系统会维护一个**动态基准线**。
    *   起初，系统可能设置置信度阈值为 0.9。随着运行，如果发现 0.85 的回答用户也很满意，系统会自动下调阈值到 0.85，从而在不牺牲满意度的情况下**节省成本**。
*   **Semantic Cache 增强**:
    *   缓存不是死的。当用户对某个新问题的回答点赞时，这个问答对会被高优先级写入 Semantic Cache。
    *   随着时间推移，缓存库里积累了大量经过验证的“黄金问答”，系统对于类似问题的响应会越来越快、越来越准。
*   **LoRA 权重动态加载 (Adaptive LoRA)**:
    *   这是本项目的核心特色。系统会根据长期流量特征，识别出新的热门领域（比如突然大家都在问 "Rust编程"）。
    *   后台训练管线可以自动触发针对该领域的 LoRA 微调，生成一个新的 `rust_adapter`。
    *   Router 检测到新 LoRA 可用后，会自动将其热加载到模型中。下一次遇到 Rust 问题，系统就变聪明了。

### 总结图示

```mermaid
graph TD
    User[用户 Query] --> Router[路由决策]
    Router --> Model[LLM 推理]
    Model --> UserResponse[返回结果]
    
    UserResponse --> Feedback[用户反馈 (👍/👎)]
    Feedback --> DataLake[数据湖 (Replay Logs)]
    
    DataLake --分析--> SignalOptimizer[信号优化器]
    SignalOptimizer --调整阈值/关键词--> ConfigUpdate[动态配置更新]
    
    DataLake --训练数据--> LoRATraining[LoRA 微调管线]
    LoRATraining --新 Adapter--> Model
```

通过这个闭环，系统不仅是在服务用户，更是在**利用用户的使用行为来训练自己**，实现越用越强。
