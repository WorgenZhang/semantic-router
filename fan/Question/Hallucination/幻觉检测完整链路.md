    └→ handleRequestBody()                          # processor_req_body.go:100

              └→ setFactCheckFromSignals()            # req_filter_fact_check.go:15
                   ├→ ctx.FactCheckNeeded = true/false   ← 如果信号匹配到 "needs_fact_check"
                   └→ checkRequestHasTools()           # req_filter_fact_check.go:49
                        ├→ 检查 RAG 检索上下文
                        ├→ 检查请求中的 tools 定义

                             → ctx.HasToolsForFactCheck = true
                             → ctx.ToolResultsContext = "工具返回的上下文内容"

  此阶段在 RequestContext 中设置的关键字段：
  - ctx.FactCheckNeeded — 是否需要事实核查
  - ctx.HasToolsForFactCheck — 是否有工具上下文可用于 grounding
  - ctx.ToolResultsContext — 工具返回/RAG 检索的事实基础文本
  - ctx.VSRSelectedDecision — 匹配的 Decision（含幻觉检测插件配置）

  ---
  触发条件总结

  幻觉检测不会在以下情况运行：
  1. Streaming 响应 — handleResponseBody 中 streaming 分支直接 return，不走幻觉检测
  2. Classifier 未配置幻觉检测模型
  3. Decision 未启用 hallucination 插件（Enabled: false）
  4. 请求不需要事实核查 — 信号评估未匹配 needs_fact_check
  5. 无工具上下文 — 请求中没有 tool results 也没有 RAG 检索内容（此时走 checkUnverifiedFactualResponse 分支）

  幻觉检测会运行的场景：
  用户发送一个匹配了某个 Decision（且该 Decision 启用了 hallucination 插件）的非流式请求，信号评估判定"需要事实核查"，并且请求中携带了 tool results 或 RAG
  上下文作为 grounding 依据。LLM 返回响应后，对响应内容与 grounding 上下文做对比检测。
