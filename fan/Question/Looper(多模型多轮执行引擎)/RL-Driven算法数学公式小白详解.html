零、为什么叫"RL-Driven"？它真的是强化学习吗？

你的疑问完全合理

如果你学过强化学习（RL），你会觉得这里的算法看起来更像统计学——更新 Beta 分布、从分布里采样、选最大值——这跟我们印象中的"RL"（神经网络 + 策略梯度 + 奖励函数 + 训练 epoch）差太远了。

你说得对，它确实不是"深度强化学习"（Deep RL）。但它是强化学习的一个经典子领域。

强化学习的本质定义

强化学习的核心不是神经网络，而是一个交互框架：

强化学习 = 智能体（Agent）与环境（Environment）的循环交互：

1. 智能体观察状态（State）
2. 智能体选择动作（Action）
3. 环境返回奖励（Reward）
4. 智能体更新策略（Policy）
5. 回到第 1 步

只要满足这个循环，就是强化学习。跟用不用神经网络无关。

对应到 RL-Driven 算法

RL 概念在本算法中的对应
智能体 (Agent)路由系统（Looper）
环境 (Environment)用户 + 各个 LLM 模型
状态 (State)每个模型的 Beta(α, β) 参数
动作 (Action)选择哪个/哪些模型来回答
奖励 (Reward)用户的正/负反馈
策略 (Policy)Thompson Sampling（从分布采样选最大）
策略更新α++ 或 β++（更新 Beta 分布）

所以它完全符合强化学习的定义——只是策略更新规则恰好是贝叶斯统计更新，而不是梯度下降。

更准确地说，它是哪种 RL？

Multi-Armed Bandit（多臂老虎机）

这是强化学习中最简单的子问题：

你面前有 N 台老虎机（每台对应一个模型）
每台老虎机的中奖概率不同，但你不知道具体是多少
你每次只能拉一台（选一个模型）
拉完之后看结果（用户反馈）
目标：用最少的尝试次数，找到最好的那台，并尽可能多地拉它

这就是 Multi-Armed Bandit 问题。
Thompson Sampling 是解决这个问题的经典最优算法之一。

RL 的光谱：从简单到复杂

简单 ◄──────────────────────────────────────────────────► 复杂 Multi-Armed Contextual Tabular Deep RL Bandit Bandit RL (DQN, PPO...) │ │ │ │ │ │ │ │ "选哪台机器" "根据场景选" "考虑状态转移" "用神经网络" │ │ │ │ │ │ │ │ ┌─────────┐ │ │ │ │ ★我们在这 │ │ │ │ └─────────┘ │ │ │ │ │ │ Thompson Sampling LinUCB Q-Learning Actor-Critic ε-Greedy Neural Bandit SARSA TRPO, PPO UCB Monte Carlo SAC, TD3

那为什么不叫"Bandit-Driven"？

几个原因：

  • 学术传统：Multi-Armed Bandit 在很多教材里被归入 RL 的第一章。Sutton & Barto 的经典 RL 教材就是从 Bandit 开始讲的。
  • 论文命名：Router-R1 论文用了 "RL" 这个更广为人知的术语，因为它强调的是"从交互反馈中学习"这个核心理念。
  • 未来扩展性：当前实现是 Bandit，但框架设计上预留了升级为 Contextual Bandit（根据问题类型选模型）甚至更复杂 RL 的空间。
总结你的疑问：

你说"更偏统计"——对，Thompson Sampling 本身是贝叶斯统计方法。
但它被用在一个在线交互决策的框架中（选动作→获奖励→更新策略→重复），这个框架就是 RL。

所以准确说法是：
RL-Driven = 用贝叶斯统计方法（Thompson Sampling）来解决一个强化学习问题（Multi-Armed Bandit）

一个直觉性的对比

❌ 不是 RL 的例子：
  "我有 1000 条历史数据，训练一个模型，部署后不再更新"
  → 这是监督学习，没有交互循环

✅ 是 RL 的例子（就是我们这个算法）：
  "每来一个请求，我选一个模型回答，看用户反馈，调整下次选择"
  → 有交互循环（选择→反馈→更新→选择...）
  → 有探索-利用权衡
  → 目标是最大化长期累积奖励

区别不在于"用不用神经网络"，而在于"有没有在线交互学习的循环"。

为什么叫 RL-Driven · 一句话总结

它是 RL 中最简单的子问题（Multi-Armed Bandit）的最优解法（Thompson Sampling）。没有神经网络不代表不是 RL——RL 的本质是"从交互反馈中学习决策"，而这恰恰是这个算法在做的事。

一、Beta 分布 — "对模型好坏的信念"

先回答一个问题：什么是"分布"？

"分布"就是描述一个值可能落在哪里的方式。比如说你抛硬币，正面朝上的概率可能是 0.5——但你不确定，也许是 0.4~0.6 之间的某个值。"分布"就是用来描述"你有多相信这个值是 0.4、0.5 还是 0.6"。

想象你新搬到一个城市，附近有 3 家餐厅，你不知道哪家好吃。

你心里对每家餐厅有个模糊的印象："可能好吃，也可能难吃，我不确定。"

这个"不确定的印象"就是一个分布——它不是一个固定的数字，而是一个范围。

Beta 分布是什么？

Beta 分布是专门用来描述"一个概率值可能是多少"的分布。它只有两个参数：

Beta(α, β)

α = "成功次数" + 1（可以理解为"好评数 + 1"）
β = "失败次数" + 1（可以理解为"差评数 + 1"）

为什么要 +1？因为在什么数据都没有的时候，我们设 α=1, β=1，表示"完全不知道，好坏各半"。这个 +1 叫做先验（prior），是我们在看到数据之前的默认信念。

Alpha 和 Beta 怎么影响形状？

Beta(1,1) → 完全平坦（什么都不知道） 概率 ▲ 1 │ ████████████████████████████████ │ ████████████████████████████████ │ ████████████████████████████████ └──────────────────────────────────► 模型好的概率 0 1 Beta(5,2) → 偏右（倾向认为模型好） 概率 ▲ 1 │ ████████ │ ██████████████████ │ ████████████████████████████ │ ████████████████████████████████████ └──────────────────────────────────► 模型好的概率 0 1 Beta(2,8) → 偏左（倾向认为模型差） 概率 ▲ 1 │ ██████ │ ██████████████ │ ██████████████████████ │ ██████████████████████████████ └──────────────────────────────────► 模型好的概率 0 1

均值公式（你认为这个模型有多好）

均值 = α / (α + β)

例子：
Beta(1, 1) → 均值 = 1/(1+1) = 0.50 （完全不确定）
Beta(5, 2) → 均值 = 5/(5+2) = 0.71 （偏好）
Beta(2, 8) → 均值 = 2/(2+8) = 0.20 （很差）
Beta(50, 5) → 均值 = 50/55 = 0.91（很棒）

方差公式（你有多确定这个判断）

方差 = (α × β) / ((α + β)² × (α + β + 1))

方差越小 → 你越确定
方差越大 → 你越不确定

例子：
Beta(1, 1) → 方差 = 1/(4×3) = 0.083 （非常不确定）
Beta(5, 2) → 方差 = 10/(49×8) = 0.026 （中等确定）
Beta(50, 5) → 方差 = 250/(3025×56) = 0.0015 （非常确定）

餐厅类比：

你去了一家餐厅 2 次，1 次好吃 1 次难吃 → Beta(2, 2)，均值 0.5，方差大（你不确定它到底好不好）

你去了另一家 100 次，90 次好吃 10 次难吃 → Beta(91, 11)，均值 0.89，方差很小（你非常确定它好吃）

Beta 分布一句话总结

Beta(α, β) 就是用"好评数"和"差评数"来描述你对"模型好的概率"的信念。数据越多，信念越坚定（方差越小）。

二、Thompson Sampling — "掷骰子选模型"

核心问题

你有 3 个模型，每个模型维护一个 Beta 分布。现在来了一个用户请求，你该选哪个模型来回答？

最简单的做法是：选均值最高的。但这有一个问题——

如果你总是选均值最高的，你就永远不会去试新模型。

假设模型 A 早期碰巧表现好（均值 0.8），新加入的模型 C 可能更好但你永远不去试，就永远不知道。
这就是经典的"探索-利用困境"（Exploration-Exploitation Dilemma）。

Thompson Sampling 的天才想法

不是选均值最高的，而是：从每个模型的 Beta 分布里随机抽一个数，选抽到数字最大的那个模型。

对每个模型 m：
  从 Beta(α_m, β_m) 中随机采样一个值 → sample_m

选择：selected_model = argmax(sample_m) （选采样值最大的那个）

掷骰子类比：

每个模型有一个"偏心骰子"。表现好的模型的骰子倾向掷出高数字，表现差的倾向掷出低数字，新模型的骰子完全随机。

每次来请求时，所有模型同时掷骰子，谁掷的点数高，谁就上场回答。

这样：表现好的模型大多数时候会赢，但新模型偶尔也能掷出高点数而获得机会。

采样的数学实现（Gamma 分布法）

计算机怎么从 Beta(α, β) 里抽一个随机数？用一个巧妙的技巧：

要从 Beta(α, β) 中采样一个值：

第1步：g1 = 从 Gamma(α, 1) 中采样一个随机数
第2步：g2 = 从 Gamma(β, 1) 中采样一个随机数
第3步：sample = g1 / (g1 + g2)

结果 sample 一定在 [0, 1] 之间 ✓

你不需要理解 Gamma 分布是什么。只需知道这是一个数学上等价的计算技巧。就像你不需要知道 CPU 怎么做除法，你只需要知道 5/3 = 1.67。

3 个模型进行 Thompson Sampling：

模型 A：Beta(α=10, β=2) ← 之前表现不错
  g1 = Gamma(10, 1) 采样得到 9.3
  g2 = Gamma(2, 1)  采样得到 1.8
  sample_A = 9.3 / (9.3 + 1.8) = 0.84

模型 B：Beta(α=3, β=7) ← 之前表现不太好
  g1 = Gamma(3, 1) 采样得到 2.1
  g2 = Gamma(7, 1) 采样得到 7.5
  sample_B = 2.1 / (2.1 + 7.5) = 0.22

模型 C：Beta(α=1, β=1) ← 新模型，什么都不知道
  g1 = Gamma(1, 1) 采样得到 0.9
  g2 = Gamma(1, 1) 采样得到 0.4
  sample_C = 0.9 / (0.9 + 0.4) = 0.69

本轮选择：模型 A（0.84 最高）

但注意！模型 C 的 0.69 已经很接近了——下次它完全可能
通过随机性掷出比 A 更高的数，这就是"探索"发生的时刻。

Thompson Sampling 一句话总结

从每个模型的"信念分布"里掷骰子，选点数最高的。表现好的模型骰子偏高（经常赢），新模型骰子随机（偶尔赢得探索机会）。

三、多轮选择 — "选 Top-K 并行调用"

为什么不只选 1 个？

在实际使用中，如果你只选 1 个模型，万一它这次回答不好怎么办？所以 RL-Driven 允许你同时选 K 个模型，并行调用，然后从中选最好的。

选择流程

配置：max_rounds = K（比如 K=3，同时选 3 个模型）

第1步：对所有候选模型进行 Thompson Sampling
  model_A: sample = 0.84
  model_B: sample = 0.22
  model_C: sample = 0.69
  model_D: sample = 0.55

第2步：按 sample 值从高到低排序
  [A=0.84, C=0.69, D=0.55, B=0.22]

第3步：选前 K 个
  K=3 → 选 [A, C, D]

第4步：并行调用这 3 个模型，都回答同一个问题

成本感知加成（可选）

如果启用了"成本感知"模式，在采样后会乘以一个成本奖励系数：

adjusted_sample_m = sample_m × cost_bonus(m)

cost_bonus 的含义：便宜的模型有加成，贵的模型有惩罚

例子：
model_A（贵）：sample=0.84 × cost_bonus=0.9 = 0.756
model_C（便宜）：sample=0.69 × cost_bonus=1.2 = 0.828

启用成本感知后，便宜的模型 C 反而排到了前面！

餐厅类比：

你饿了，不想只去 1 家餐厅碰运气。你点了 3 家外卖（并行调用 3 个模型），等全到了之后挑最好吃的那份吃。

如果你还在乎钱（成本感知），那么贵的餐厅需要明显更好吃才会被你选中。

场景：用户问了一个代码问题，max_rounds = 2

Thompson Sampling 结果：
  codellama-34b:  sample = 0.77  ← 第1名
  llama-3-70b:    sample = 0.65  ← 第2名
  llama-3-8b:     sample = 0.41  ← 第3名（淘汰）
  mistral-7b:     sample = 0.33  ← 第4名（淘汰）

选中：[codellama-34b, llama-3-70b]
并行调用这两个模型 → 各自返回一个回答
然后进入"响应聚合"环节，决定最终用谁的回答

多轮选择一句话总结

Thompson Sampling 选出 Top-K 个模型并行调用，K 越大质量越高但成本也越高。可以启用成本感知来偏向便宜模型。

四、反馈更新 — "越用越聪明"

核心机制

Thompson Sampling 之所以能"越用越准"，是因为每次使用后都会根据反馈更新 Beta 分布。

当收到用户反馈时：

情况1：用户说"这个回答好"（正反馈）
  α_winner += weight   ← 给获胜模型加"好评"

情况2：用户说"这个回答不好"（负反馈）
  β_loser += weight   ← 给失败模型加"差评"

其中：
  weight = feedback_weight × confidence
  feedback_weight = 配置值（默认 1.0）
  confidence = 反馈的可信度（0~1）

什么是 weight（权重）？

不是所有反馈都一样重要：

反馈类型confidence 值说明
用户手动点赞/踩1.0最可信，用户明确表态
用户选择了某个回答0.8隐式偏好
用户没有重新提问0.3弱信号，可能只是懒得重试
自动评估（如置信度）0.5机器判断，有噪声

完整的反馈更新过程：

初始状态：
  model_A: Beta(α=5, β=2)  均值=0.71
  model_B: Beta(α=3, β=3)  均值=0.50

这次选了 model_A 和 model_B 并行回答

用户点赞了 model_A 的回答（显式正反馈）：
  weight = 1.0 × 1.0 = 1.0
  model_A: α += 1.0 → Beta(α=6, β=2)  均值=0.75 ↑

用户没有对 model_B 做任何操作（隐式负反馈）：
  weight = 1.0 × 0.3 = 0.3
  model_B: β += 0.3 → Beta(α=3, β=3.3)  均值=0.476 ↓

更新后：
  model_A: Beta(6, 2)    均值 0.75（信心增加）
  model_B: Beta(3, 3.3)  均值 0.476（略微下降）

为什么不直接用均值排序？

看了反馈更新，你可能会想："既然每次更新 α 和 β，那直接看均值不就好了？"

不行！因为均值忽略了"你有多确定"这个信息。

model_X: Beta(2, 1)  均值=0.67 ← 只试过2次，全成功
model_Y: Beta(80, 20) 均值=0.80 ← 试过100次，大部分成功

如果只看均值，肯定选 Y。
但 X 只试了 2 次就全成功，也许它其实比 Y 更好？

Thompson Sampling 的做法：
  X 的方差大 → 采样结果波动大 → 有时能采到 0.9+
  Y 的方差小 → 采样结果稳定在 0.78~0.82

所以 X 仍然有机会被选中（探索），而 Y 大多数时候会赢（利用）

反馈更新一句话总结

用户觉得好 → 给模型加好评（α++）；觉得差 → 加差评（β++）。反馈可以有不同的权重。随着反馈积累，系统对每个模型的认知越来越准。

五、响应聚合 — "最终选谁的回答"

问题

多轮选择选了 K 个模型并行调用，每个都返回了回答。那最终给用户看哪个？

当前实现的策略

best_model = argmax_m { score_m }

其中 score_m = 该模型在 Thompson Sampling 时的采样值

简单说：谁在"掷骰子"环节掷得最高，就用谁的回答
注意：当前实现没有做文本级融合（不像 ReMoM 那样把多个回答合并成一个）。它只是简单地选择分数最高的那个模型的回答作为输出。未来可能会加入更复杂的聚合策略。 
选中了 3 个模型并行回答用户问题："Python 的 GIL 是什么？"

Thompson Sampling 采样结果：
  model_A: score = 0.84 → 回答："GIL 是全局解释器锁..."
  model_C: score = 0.69 → 回答："GIL (Global Interpreter Lock)..."
  model_D: score = 0.55 → 回答："Python 的 GIL..."

聚合策略：选 score 最高的
  → 最终输出 model_A 的回答："GIL 是全局解释器锁..."

为什么不用回答质量来选？

你可能会问："为什么不让另一个模型来评估哪个回答更好？"这是个好问题：

  • 评估本身需要额外调用，增加延迟和成本
  • Thompson Sampling 的采样值本身就是对"模型质量"的估计——长期来看，好模型的采样值本来就更高
  • 用户反馈会修正这个估计，所以系统会越来越准

响应聚合一句话总结

并行调用的 K 个模型中，直接选 Thompson Sampling 分数最高的那个模型的回答。简单粗暴但有效——因为分数本身就代表了对模型质量的估计。

六、探索 vs 利用 — "老店 vs 新店"

这是什么问题？

你每天中午要选一家餐厅吃饭：

利用（Exploit）：去你已知最好吃的那家 → 稳定获得高满意度

探索（Explore）：去你没试过的新店 → 可能发现更好的，但也可能踩雷

如果你永远只去老店（纯利用），你就永远不知道新店可能更好。
如果你每天都去新店（纯探索），你的平均满意度会很低。

最优策略是两者平衡：大部分时间去老店，偶尔试试新店。

Thompson Sampling 怎么自动平衡的？

关键在于：方差大的模型有更大的"逆袭"概率。

三种模型状态
状态1️⃣ 老牌好模型（高 α，低 β）
  Beta(50, 5)  均值=0.91，方差=0.0015
  采样范围大约在 [0.85, 0.96]
  → 几乎每次都能采到高值 → 高概率被选中
  → 这就是"利用"

状态2️⃣ 新模型（α=1, β=1）
  Beta(1, 1)  均值=0.50，方差=0.083
  采样范围大约在 [0.05, 0.95]（非常宽！）
  → 有时采到 0.9+（逆袭成功！）→ 有时被选中
  → 这就是"探索"

状态3️⃣ 已被验证很差的模型（低 α，高 β）
  Beta(2, 20)  均值=0.09，方差=0.004
  采样范围大约在 [0.02, 0.18]
  → 几乎不可能采到高值 → 几乎不会被选中
  → 这就是"自动淘汰"

数学上的直觉

被选中的概率 ≈ P(从自己的分布里采出全场最高值)

影响因素：
1. 均值越高 → 采样中心越高 → 被选概率越大（利用）
2. 方差越大 → 采样波动越大 → 偶尔采出极高值的概率越大（探索）

随着数据积累：
- 好模型：α 增大 → 均值升高 + 方差缩小 → 稳定高分 → 持续被利用
- 差模型：β 增大 → 均值降低 + 方差缩小 → 稳定低分 → 自动淘汰
- 新模型：数据少 → 方差大 → 有"黑马"机会 → 被探索

和其他策略的对比

策略做法问题
贪心（Greedy） 永远选均值最高的 永远不探索新模型，可能错过更好的
ε-贪心 90% 选最好的，10% 随机选 随机探索效率低，好模型差模型都可能被随机到
UCB（置信上界） 选"均值 + 不确定性"最高的 确定性的，缺乏随机性带来的多样性
Thompson Sampling 从分布中采样，选最高的 自动平衡，有数学最优保证 ✓

完整时间线演示：

═══ 第 1 天：3 个模型都是新的 ═══
  A: Beta(1,1) 均值 0.50  │  B: Beta(1,1) 均值 0.50  │  C: Beta(1,1) 均值 0.50
  → 纯随机选择（三个骰子一样）

═══ 第 10 天：有了一些反馈 ═══
  A: Beta(8,3) 均值 0.73  │  B: Beta(4,7) 均值 0.36  │  C: Beta(3,2) 均值 0.60
  → A 最常被选（利用），B 很少被选，C 偶尔被选（还在探索）

═══ 第 100 天：格局稳定 ═══
  A: Beta(70,15) 均值 0.82  │  B: Beta(8,50) 均值 0.14  │  C: Beta(40,20) 均值 0.67
  → A 是主力（稳定利用）
  → B 基本淘汰（几乎不选）
  → C 是备选（偶尔被选，补充多样性）

═══ 第 101 天：新模型 D 上线 ═══
  D: Beta(1,1) 均值 0.50，方差大
  → D 有一定概率被选中（探索新兵）
  → 如果 D 表现好，几天内就能追上 C
  → 如果 D 表现差，几天内就被淘汰

探索 vs 利用 一句话总结

Thompson Sampling 通过方差自动平衡：已验证好的模型方差小、均值高，稳定被选（利用）；新模型方差大，偶尔采出高值（探索）；验证差的模型均值低、方差小，自动淘汰。无需手动调参。
